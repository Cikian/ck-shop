# 商品详情页「真实统计」与评价模块 · 接口契约

> 起因：商品详情页统计行（已售 2068 / 4.5 / 收藏数 2653）里的数字全部来自 `ck_shop_product`
> 的冗余列，而这些列当年是被演示脚本直接写死的常量，**没有任何业务流水能对上**。
> 本契约定义：这三个数字各自的真实来源、口径、以及为「评分/评价数」补上的真实评价模块。

生成日期：2026-10-21

---

## 0. 三个数字的真实来源（口径）

| 统计项 | 展示文案 | 真实来源 | 口径 |
|---|---|---|---|
| 已售 | `shop.sold` → 「已售 N」 | `ck_shop_order_item` ⋈ `ck_shop_order` | 成交件数**扣掉已退件数**：`SUM(quantity - refund_quantity)`，只统计已收过钱的订单（`pay_status IN ('PAID','PARTIAL_REFUND')`）、未归档（`del_flag=0`）、非取消/关闭（`order_status NOT IN ('CANCELLED','CLOSED')`）。全额退款会把订单置为 `CANCELLED + REFUNDED`，因此自动掉出统计 |
| 评分 / 评价数 | 统计行「4.5」+ 评价区「N 条评价」 | `ck_shop_product_review` | `rating` 1–5 的平均值（保留 1 位小数）与条数；只统计 `del_flag=0 AND status='Y'`（未被后台隐藏）的评价 |
| 收藏数 | 「收藏数 N」 | `ck_shop_favorite` | `del_flag=0` 的关系行数（与「我的收藏」列表同一个口径，不再用冗余列做展示值） |

**核心原则**：读接口一律**实时聚合**上表来源，绝不把冗余列当展示值；
冗余列（`sales_count / month_sales_count / favorite_count / review_count / rating_avg`）
降级为**排序与后台统计用的缓存**，由迁移脚本与写入事务同步维护。
这样即使缓存漂移，页面上也不会出现"编出来的数字"。

## 1. 数据模型：`ck_shop_product_review`

迁移脚本：`V3.9.5_15__shop_product_review.sql`

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | varchar(36) | 主键 |
| `product_id` | varchar(36) | 商品 ID（`ck_shop_product.id`） |

| `sku_combination_id` / `sku_name` | varchar(36) / varchar(255) | 下单时的规格快照（展示「黑色 / 256G」） |

| `content` | varchar(500) | 文字内容，可空（只打分不写字是允许的） |
| `anonymous` | tinyint(1) | 1 = 匿名（展示时昵称打码） |

`idx_review_user(user_id, create_time)`。

## 2. 店铺端接口（Java，`/shop/review/store/**`）

### 2.1 评价汇总（匿名可访问，`@IgnoreAuth`）

`GET /shop/review/store/summary?productId=xxx`

```json
{
  "productId": "2109574599579942914",
  "ratingAvg": 4.5,
  "reviewCount": 12,
  "distribution": [
    { "rating": 5, "count": 9 },
    { "rating": 4, "count": 2 },
    { "rating": 3, "count": 1 },
    { "rating": 2, "count": 0 },
    { "rating": 1, "count": 0 }
  ]
}
```

- `ratingAvg` 无评价时为 `0`（前端按 `reviewCount === 0` 整块不渲染，见第 5 节）；
- `distribution` **恒定返回 5 项**（5→1），没有评价的档位 `count: 0`，前端不需要补位。

### 2.2 评价列表（匿名可访问）

`GET /shop/review/store/list?productId=xxx&pageNo=1&pageSize=10`

```json
{
  "records": [
    {
      "id": "2111000000000000001",
      "rating": 5,
      "content": "做工扎实，物流很快",
      "username": "cik***",
      "anonymous": false,
      "skuName": "黑色 / 256G",
      "createTime": "2026-10-21 12:00:00"
    }
  ],
  "total": 12, "size": 10, "current": 1, "pages": 2
}
```

- 昵称**在后端就打码**（保留首 2 位与末 1 位：`cikian` → `ci***n`），不把完整账号发给任何人；
  `anonymous = true` 时 `username` 直接为 `null`，由前端按 i18n 显示「匿名用户」；
- 按 `create_time DESC` 排序；
- 分页结构是 MyBatis-Plus 的 `IPage`，与项目其它列表接口一致。

### 2.3 待评价明细（需登录）

`GET /shop/review/store/pending?orderNo=SO2026...`

```json
[
  {
    "orderItemId": "2110329173458698242",
    "productId": "2109574599579942914",
    "productName": "轻量户外冲锋衣",
    "skuName": "黑色 / L",
    "productImage": "https://...",
    "quantity": 2,
    "reviewed": false
  }
]
```

- 只返回**属于当前登录人**、且订单满足"已支付且未取消/关闭"的明细行；
- `reviewed = true` 表示已经评价过（前端置灰「已评价」），`false` 才给「去评价」按钮；
- 订单不存在 / 不属于本人 → 空数组（不区分"没有"和"不是你的"，避免越权探测）。

### 2.4 提交评价（需登录）

`POST /shop/review/store/submit`

```json
{ "orderItemId": "2110329173458698242", "rating": 5, "content": "很满意", "anonymous": false }
```

```json
{
  "review": { "...": "同 2.2 的 records[i]" },
  "summary": { "...": "同 2.1" }
}
```

校验（全部失败都抛业务异常，前端展示 `message`）：

| 情况 | 结果 |
|---|---|
| 未登录 | 401（Shiro 拦截） |
| `rating` 不在 1–5 | 400/业务异常「请选择 1-5 星评分」 |
| `content` 超过 500 字 | 业务异常「评价内容不能超过 500 字」 |
| 明细不存在 / 不属于本人 | 业务异常「订单明细不存在」 |
| 订单未支付或已取消/关闭 | 业务异常「该订单当前不可评价」 |
| 已评价过 | 业务异常「该商品已评价过」 |

提交成功后**同一事务内**回写 `ck_shop_product.review_count / rating_avg`（缓存列），
并回读真实汇总返回，不做前端式心算。

## 3. 商品接口的变化（`/shop/product/store/**`）

`GET /shop/product/store/detail` 与 `/list` 返回的
`salesCount / monthSalesCount / reviewCount / ratingAvg / favoriteCount`
**改为实时聚合值**（来源见第 0 节），字段名与类型保持不变 —— 前端不需要改解析。

| BFF 路由 | 后端接口 | 鉴权 |
|---|---|---|
| `GET /api/review?productId=&pageNo=&pageSize=&lang=` | summary + list（一次并行取回，返回 `{ summary, page }`） | 匿名 |

## 5. 展示规则（必须遵守）

1. **0 值一律不渲染**：`reviewCount = 0` → 评价区整块不出现（锚点也跟着消失）；
   `salesCount = 0` → 不出现「已售 0」；`favoriteCount = 0` → 不出现「收藏数 0」；
   三项都为 0 → 整个统计行不渲染。
2. **不编造**：没有评价就是没有评价，不显示"暂无评价，快来抢沙发"之外的任何占位数字/假好评。
3. 统计行与评价区**同源**：统计行的评分来自 `summary.ratingAvg`，评价区标题旁的
   「N 条评价」来自 `summary.reviewCount`，不允许出现两处不一致。
