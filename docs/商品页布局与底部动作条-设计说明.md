### 2.1 容器与分栏

- 本页容器宽度从 `max-w-7xl`（1280）放宽到 **`max-w-[1600px]`**，否则 60/40 分栏后图集只有 ~740px，视觉缩水明显。
- 分栏：`grid-template-columns: minmax(0, 3fr) minmax(0, 2fr)`。
- **列间距不用 grid `gap`，用左列 `lg:pr-8` 实现**：用 gap 时右列只有内容区的 39.1%，
  与验收 #2「右列 ≈40% ±1px」冲突；`pr-8` 产生同样的 32px 视觉间距，同时左右列严格 60%/40%
  （实测 0.3999）。左列 = 图集 + 锚点 + 四个区块；右列 = 商品信息面板。

### 2.2 右列吸顶（关键实现口径）

- 右列外层是 grid 子项，`align-self: stretch`（高度随整行 = 左右较长的一边），内部面板 `position: sticky`。
- **不设置任何 `overflow: auto/scroll`**：右侧永远没有自己的滚动条，滚轮事件直接落到 window。
- sticky 的 `top` 由脚本按内容高度动态计算（SSR 首帧用 header 高度兜底）：

  ```
  headerH = 实测 header 高度
  barH    = 动作条高度
  barTop  = innerHeight - 32 - barH                    // 动作条（浮层底）顶边：离底 32px（第 3 轮）
  panelH  = 面板内容高度
  natural = 面板未吸顶时的自然位置（= aside 矩形 + panel.offsetTop）
  top     = panelH <= (barTop - 16 - natural) ? natural               // 不高：钉在自然位置，滚动位移恒为 0
                                              : barTop - 16 - panelH  // 超长：先随页面滚动，全部露出后再吸底
  ```

  - 内容不高时：面板钉在 header 下方，左侧滚动它不动；
  - 内容超长时：面板先随页面**一起正常滚动**（等于"两边同时滚动"），滚到面板底部对齐动作条上方后钉住；
  - 这样既满足"吸顶/始终可见"，又满足"只有一个浏览器滚动条、页面高度取更长一边"。
- 重新计算时机：`resize`、面板内容尺寸变化（`ResizeObserver`，规格切换会改变高度）、语言切换。滚动本身**不需要**重算（sticky 由浏览器处理），避免每帧布局抖动。
- ⚠️ 第 3 轮修正：`top` 不再用 `headerH + 16`（那比面板的自然位置高 7px，会让右侧在开滚时先向上挪 7px），改为直接取**自然位置**，见 9.1 第 2 条。

### 2.3 底部动作条

| 项 | 口径 |
|----|------|
| 定位 | `position: fixed; right: 0; bottom: 0; width: 40%`（`lg:` 生效）；~~桌面离底 20px（`lg:bottom-5`）~~ → **第 3 轮改为离底 32px（`lg:bottom-8`），见 9.1/9.2** → **现为离底 56px（`lg:bottom-14`），见第十二节**；移动端 `width: 100%` + `bottom: 0` + `env(safe-area-inset-bottom)` |
| 视觉 | ~~无白色背景、无描边、无阴影~~ → **第 3 轮改为不透明浮层底 `.ui-action-dock`（radius 28 / #fff6f2 / 双向 30px 投影），见 9.1**；按钮自身保留圆角/配色与轻微投影 |
| 点击穿透 | 透明容器必须 `pointer-events: none`、只有按钮行 `pointer-events: auto`，否则透明区域会挡住右栏下层内容的点击 |
| 加入购物车 | 黄色（沿用现有 `--color-accent` 系），图标 `shopping-cart` + 文案；未登录文案仍为「登录后加入购物车」 |
| 立即购买 | 品牌主色（沿用现有主 CTA 色），图标 `zap`（闪电）+ 文案；未登录仍为「登录后立即购买」 |
| 收藏 | 中性色 pill（`.ui-pill-fav`：不透明白色底（`--color-surface`）+ 描边，避免透明按钮在浅底上看不清；**不能再用 `.ui-pill-ghost`，它的 `background: transparent` 会盖掉 Tailwind 的 `bg-*`，见 9.1**），星形图标（已收藏实心）+「收藏 / 已收藏」；与现有收藏接口、未登录引导一致 |
| 状态 | 沿用现有语义：规格未选完给提示、库存不足禁用/提示；三处按钮都不得做本地乐观更新 |
| 层级 | 高于页面内容与锚点（z-30），低于全局 header（z-50）与 toast/modal；动作条 z-40 |
| 测量口径 | 吸顶/留白以**动作条实际 `top`** 计算（不是只减高度）：它离底后可用高度 = `barTop - headerH - 16` |

### 2.4 左列

- 移除图集上方的面包屑（`首页 > 全部商品 > 分类 > 商品名`）。
- 锚点导航：从"通栏吸顶"改为**只在左列内吸顶**（宽度 = 左列宽度）；滚动高亮与点击跳转逻辑保持不变。
- 详情区块（规格参数 / 用户评价 / 商品详情 / 类似推荐）顺序与渲染规则不变。
- 左列底部按需留白（desktop 动作条只覆盖右列，左列无需为它留白；移动端需要）。

### 2.5 图集

- 移除右上角心形收藏（保留分享按钮）；主图/缩略图逻辑不变。
- 图集左上对齐左列，宽度 100%。

### 2.6 右侧信息面板内容顺序

分类 → 标题 → 副标题 → 价格块 → 统计行 → 库存 → 规格选择 → 组合提示 → **数量** → 合计。

> 2026-10 设计稿精简（红框标注）：面板里只保留可决策的信息，重复/说教式的辅助文案全部删除——
> ① 标题上方的**商品编码**；② 规格区上方的「选择规格」小标题与「同一规格可直接点击切换…」提示条
> （规格组 legend「规格 *」已足以表意）；③ 数量下方的「支持加入购物车…」提示 + 「查看购物车」入口
> 与「品质优选 / 包邮 / 七天无理由」服务标签。交互语义不变，只是不再占版面。

- 原 `PurchaseBar` 里的"数量 + 三个按钮 + 服务标签"拆成两部分：
  - 数量、合计 → 留在右侧面板底部；
  - 三个按钮 → 移入固定动作条（新组件 `StickyPurchaseBar` / `StickyActionBar`）。

## 三、移动端（<1024px）

- 恢复单列流动布局：图集 → 信息面板（含规格、数量、服务）→ 锚点导航 → 四个区块。
- 动作条固定屏幕底部、通栏；页面底部预留动作条高度 + safe-area，避免遮挡最后一块内容。
- 信息面板不吸顶、无内部滚动。

## 四、无障碍与性能

- 动作条按钮保持可见焦点环、`aria-pressed`（收藏）、`aria-label`（图标按钮）；
- 吸顶计算用 `requestAnimationFrame` 合并 resize 回调，`ResizeObserver` 断开于 unmount；
- 尊重 `prefers-reduced-motion`（不新增动画，仅保留既有过渡）；
- 动作条不遮挡内容：右列可用高度已扣除动作条；移动端底部留白。

### 6.3 验证中发现并修掉的缺陷

| 现象 | 根因 | 修复 |
|------|------|------|
| 移动端滚到页底时，页脚最后一行被动作条盖住（footerBottom 844 > barTop 779） | 预留留白加在**页面根节点**，而 `SiteFooter` 是 `<main>` 的兄弟节点，留白出现在页脚之前 | 改为给 `document.body` 加 `padding-bottom`（桌面/卸载时清除），实测 footerBottom 755 < barTop 779 |

### 6.4 需要知晓的取舍（长面板）

演示商品（2 个规格）右栏高 **776px**；1440×900 下动作条离底 20px 后，可用高度为 **687px**
（`barTop 820 − header 117 − 16`），因此：

- **首屏**：右栏底部（数量 / 服务标签）会落到固定动作条后面；因为动作条已改为透明，
  按钮会与这些内容视觉重叠（向下滚一点即完整露出，随后与按钮自动错开）。
- **吸顶后**：为保证「底部不被动作条遮挡」，面板顶部会有约 89px 进入 fixed header 之后
  （标题行被盖住，从价格块起可见）。
- 这是「只有一个滚动条 + 吸顶 + 内容比视口高 + 动作条离底」四个约束下的必然取舍。
  窗口更高（1600×1000 可用 787px）或右栏更短时，面板可完整显示并普通吸顶（已实测）。
- 如果希望右栏始终完整可见，需要二选一：① 允许右栏内部滚动条（违背"单滚动条"）；
  ② 收紧右栏内容/间距（约需减少 ≥89px，例如把「加购提示/服务标签」两行合并或移出右栏）。

### 11.2 为什么换成 sticky 才"自然"

- `fixed + translateY` 必须每帧跟着 `scroll` 事件改 transform，真机惯性滚动时永远慢半拍 —— 观感就是"抖一下 / 轻微漂移"（桌面窗口滚动感知不明显，手机上很明显）；
- `sticky` 由浏览器合成层负责：动作条就是内容流里的一个元素，"钉在视口底" 与 "随内容上滚" 是同一条曲线，**零 JS、零延迟**，桌面/移动端行为完全一致；
- 判据（实测）：释放后再滚 200px，动作条位移正好 200px（1:1 跟手）；`getComputedStyle(root).transform` 恒为 `none`；
- 副作用（有意为之）：移动端不再给 `body` 预留底部空间 —— 动作条会随内容滚走，不会永久压住页脚。

## 十三、第 8 轮修订：左列锚点导航移出首屏（`lg:mt-16`）

**反馈**：首屏最底部露出半个「规格参数 / 用户评价 / 商品详情 / 为你推荐」条，像被裁掉一截。要求把它往下挪，第一屏不要出现。

### 13.1 为什么会露出来（纯几何问题）

- 桌面主图底边被钉在 `viewport − 56`（= 动作条浮层底底边，见第十二节），**与视口高无关**；
- 左列 row2（锚点导航 + 三区块）原本 `lg:mt-0` 紧贴主图，而锚点条自带 `pt-6`（24px）；
- 于是锚点条**条顶 = viewport − 56 + 24 = viewport − 32** → 必然有 32px 探进首屏。

### 13.2 修法（一处，且不能改在锚点的 padding 上）

| 位置 | 改动 |
|---|---|
| `pages/products/[slug].vue` 的 `data-product-sections`（左列 row2 外层） | `lg:mt-0` → **`lg:mt-16`（64px）** → 第 9 轮又收到 **`lg:mt-8`（32px）**，因为主图同时加高了 32px，见第十四节 |

- **不能**把锚点条的 `pt-6` 调大：`pt` 是 sticky 元素自身的 padding，吸顶后条子跟着 `top = header 高度`，padding 会把 chip 推到 header 下方 64px 的空中。margin 不会进入 sticky 定位，吸顶位置仍是 header 正下方。
- 留白必须 **≥ 56 − 24 = 32px** 才能把整条推到折叠线以下；取 64px 后 chip（白色药丸）顶边落在 `viewport + 32`，首屏 0px 可见（锚点条本身的 `bg-cream` 与页面同色，8px 的极窄露头也看不出来）。

### 13.3 副作用（可接受）

- 主图底边（`viewport−56`）到 chip 顶边之间是 88px 奶油色留白，视觉上就是"图与导航之间的间距"；
- 锚点条吸顶的**起点被推迟 64px**：滚到约 850px（图集完全离开视口时）才开始钉在 header 下，之前它是随页面向上滚的自然元素 —— 这正是需求想要的"先滚、再吸"。

## 十四、第 9 轮修订：主图加高成「微微的长方形」（`lg:mt-16` → `lg:mt-8`）

**反馈**：锚点条下移之后，主图与锚点条之间的空隙太大；把主图加高一点、让它变成微微的长方形，**但主图下边缘必须与视口底留一点距离**（不能贴到屏幕最底）。

### 14.1 几何（先把约束写清楚，再选数值）

设加高量 `EXTRA`：

| 量 | 公式 | 取 `EXTRA = 32` |
|---|---|---|
| 主图宽度 | 基准边长 `base = 视口高 − 56 − 图集内容顶部` | 766（与上一版完全一致） |
| 主图高度 | `base + EXTRA` | 798（宽:高 ≈ 1:1.042） |
| 主图底边 | `viewport − (56 − EXTRA)` | **viewport − 24**（距视口底 24px，满足"留点距离"） |
| 锚点条条顶 | 主图底边 + `mt` | `viewport − 24 + 32 = viewport + 8` |

**关键配对**：`EXTRA + mt = 64` 时 chip 的绝对位置保持不变（所以第 8 轮"移出首屏"的结论继续成立），

### 14.5 顺带修复：缩略图「点回上一张」大图不切换

**现象**：点缩略图切换过一次之后，再点缩略图（尤其是点回刚才那张）大图不动，只有缩略图高亮变了。

**根因**（`Gallery.vue` 的两层交叉淡入状态机）：翻层靠 `<img>` 的 `load` 事件，而**给 `<img>` 赋同样的 `src` 不会触发 `load`**。
来回点 A→B→A 时，A 往往正好停在"背面层"里 → `layerSrc[back] = A` 是空操作 → 永远等不到 `load`
→ `activeLayer` 不翻转 → 大图停在上一次的结果。

**修复**（只动状态机，模板/样式零改动）：

| 改动 | 作用 |
|---|---|
| 新增 `loadedSrc: Set<string>`（成功加载过的图片 URL，在 `onLayerLoad` 里登记） | 命中就直接翻层，不等 `load` 事件 |
| `watch` 里记录"背面层是否已经是这张"（`backHoldsSameSrc`）；命中 `loadedSrc` → 立刻 `activeLayer = back` | 修掉 A→B→A 卡住 |
| 背面层已经是这张、却既没加载成功也不会再发 `load`（上次失败）时：先清空 `layerSrc[back]` 卸载 `<img>`，下一 tick 再写回 | 强制重新发请求，避免"点了再也不动" |
| `onLayerLoad` 先登记 `loadedSrc`、再判断"是否当前主图" | 旧图迟到的 `load` 仍不会误翻层，但它的 URL 会被记住 |

修复前 **8/9**（第 4 步 A→B→A 卡住，可见层仍是上一张），修复后 **9/9**。
