## 一、需求与实现范围

| # | 需求 | 实现方式 |
|---|------|----------|
| 1 | 管理端新增/编辑商品时编辑「商品详情」 | `ProductForm` 抽屉新增「商品详情」页签：8 种模块竖向搭建（图片 / 多图宫格 / 图文 / 文本 / 富文本 / 视频 / 标题 / 分隔线），支持新增、编辑、上移下移、拖拽、删除 |
| 2 | 编辑方式取舍 | **结构化模块 + 模块内富文本**（已与需求方确认）：比纯富文本更可控、移动端排版稳定、预览与店铺端同构；富文本仅作为其中一种模块 |
| 3 | 商品详情支持多语言 | 模块与参数都按 `language_code` 独立存储；管理端每种语言一套；提供「复制到其它语言」；店铺端按请求语言返回，缺失时整体回退 |
| 4 | 编辑时实时预览 | 右侧预览面板与左侧共用同一份响应式数据（无需保存）；可切「桌面 / 移动 390px」；图片可点开放大 |
| 5 | 店铺端完成商品详情 | 8 种模块渲染器 + 图片灯箱 + 视频嵌入 + 富文本清洗；区块顺序按需求调整为**规格参数 → 用户评价 → 商品详情 → 类似推荐** |
| 6 | （需求方补充）规格参数 KV | 管理端「规格参数」页签自由录入 Key-Value；店铺端渲染全部 KV；支持从规格配置生成、复制到其它语言 |

## 二、数据模型与迁移

新增两张表（DDL 见 `ck-server/db/ck-shop-product-detail.sql` 与 Flyway `V3.9.5_13__shop_product_detail.sql`）：

| 表 | 用途 | 关键列 |
|----|------|--------|
| `ck_shop_product_detail_block` | 详情模块 | `product_id` / `language_code` / `block_type` / `content`(JSON 文本) / `sort_order` |
| `ck_shop_product_param` | 规格参数 KV | `product_id` / `language_code` / `param_name` / `param_value` / `sort_order` |

- 两表都**没有 `del_flag`**：内容型数据、无外部引用、无唯一索引，删除为物理删除（理由写在契约 1.1）。
- 已在本机开发库执行 DDL，并补写 Flyway 历史：

```

```

- 未修改任何既有列、未删除/改写既有数据。
- 演示数据：`ck-server/db/ck-shop-product-detail-demo.sql`（幂等，仅作用于两件演示商品
  `DEMO-DIGI-001` / `DEMO-OUT-001`，生产环境勿执行）。

## 六、已知局限与后续建议

| # | 局限 | 建议 |
|---|------|------|
| 1 | 富文本清洗是「正则 + 标签/属性/协议白名单」，不是完整 HTML 解析器（契约第五节已注明） | 若将来允许非管理员写富文本，应换 jsoup/OWASP sanitizer；目前写入入口只有管理端登录用户 |
| 2 | 管理端预览与店铺端是两套 Vue 实现（两个工程无法共享构建），样式靠契约对齐 | 可考虑抽一个小型 npm 包或（更现实）用同一份 HTML 快照做视觉回归 |
| 3 | 灯箱交互未做自动化点击验证（仅结构 + 组件自测） | 后续可用 CDP 补一条点击 → 打开 → Esc 关闭的断言 |
| 4 | 视频依赖外网（B 站 / YouTube），内网环境会显示加载失败 | 需要离线场景时优先用 `file` 直链 + 自有 CDN |
| 5 | 模块/参数为整体替换语义：每次保存模块主键都会变化 | 模块不被订单引用，当前无影响；若以后要引用（如埋点），改增量 upsert |
| 6 | 未做模块级草稿/版本历史、未做 AI 一键翻译 | 属二期能力，接口已按"按语言独立"设计，扩展时不需要改表 |
| 7 | 参数 KV 不参与搜索/筛选 | 若要做参数筛选，需要额外建倒排/索引表，不能直接扫 `ck_shop_product_param` |

## 七、第 2 轮：模块间距 / 图片圆角 / 宫格列数与图片间距（2026-10-21）

### 7.1 需求

设计同事经常把**一张超长详情图切成多张**导出，运营拼到详情页里必须**看不出缝**。因此：

1. 每个模块上下左右间距默认 **0**，但可逐模块手动调（四方向）；
2. 或者用多图宫格：列数 1/2/3 快捷 + 自定义，宫格内图片四方向间距可调；
3. **任何图片组件的圆角可设置，默认无圆角**。

### 7.2 契约与数据模型变更

- 契约：[商品详情-设计契约.md](./商品详情-设计契约.md) 第 1.3（content 新字段）、**1.4（模块间距，新）**、2.1/2.2（API 字段）、3.1/3.2/3.3（管理端控件与校验）、4.3（渲染细则）。
- 数据库：`ck_shop_product_detail_block` 增加 4 列
  `margin_top / margin_right / margin_bottom / margin_left`（INT NOT NULL DEFAULT 0）。
  迁移：`V3.9.5_14__shop_product_detail_layout.sql`（可重复执行，只加列），
  已执行并补登记 `flyway_schema_history` rank 25（version 3.9.5.14）。
- content 新字段：
  - `IMAGE` / `IMAGE_TEXT`：`radius`（0–200，默认 0）
  - `IMAGE_GRID`：`columns`（1–6，默认 2）、`itemMargin{top,right,bottom,left}`（0–200，默认 0）、`radius`
- 兼容：旧数据无这些字段 → 0 / 2；**旧详情图片由圆角变直角**（需求预期的"默认无圆角"）。

### 7.3 代码落点

| 层 | 改动 |
|----|------|
| 后端 | 实体/DTO/VO/StoreVO 各加 4 个 margin 字段；`ShopDetailBlockSupport` 增加 radius/columns/itemMargin 保存校验与**读取容错**（越界夹取，不 500）；Service 保存校验 0–500 并落库、读取回填（null→0） |

### 7.5 本轮踩到的坑（都不是产品缺陷，但会误导验收）

| # | 现象 | 根因与处理 |
|---|------|-----------|
| 1 | 局部截图出来只有 16px 高的一条 | 懒加载图片尚未加载，`height:auto` 计算高度为 0；脚本改为先 `scrollIntoView` + `img.decode()` 再测量 |
| 2 | 截图中间横穿一条页头/锚点导航，看起来像"缝" | fixed/sticky 元素在整页裁剪时被渲染在裁剪区域内；脚本新增 `--hide 'header,nav.sticky'` |
| 3 | 管理端断言"中文 7 个卡片"失败，实际 10 | AntD 每个语言页签都保持挂载，`.block-card` 统计到 zh(7)+en(3)；断言口径改为 ≥7，并注明原因 |
| 4 | 预览与店铺端相邻模块间距可能不完全一致 | 两者都用普通块级元素，垂直 margin 会按 CSS 规则合并（取 max）；契约 1.4 已写明该行为，**内联值本身一致** |

### 7.6 本轮遗留

- `VIDEO` 的播放器/封面仍保留原有圆角（它不是"图片组件"，契约未给 radius 字段）；
  富文本正文内图片已改为默认无圆角（不提供模块级设置，需要圆角请用图片模块）。
- 管理端预览中的 `/`-相对图片路径依赖店铺端站点；本地从 3100 打开时这类图片会 404，
  这是预览的天生限制（真实图片应上传到 CDN/OSS 用绝对地址）。
- 间距值目前是整数 px，没有"按百分比/自适应"模式；长图在窄屏仍然 100% 宽、等比缩放，拼接关系不变。
