# 商品详情（详情模块 + 规格参数）设计契约

> 本文是本次「商品详情」功能的**唯一契约依据**：数据模型、接口字段、模块 JSON、渲染规则、
> 多语言与回退、安全约束。管理端（admin-client）、后端（ck-server）、店铺端（nuxt-shop）
> 三方都按本文实现；实现与本文冲突时以本文为准，若必须偏离请先改本文。
>
> 状态：已与需求方确认（2026-10-20）。决策要点：
> 1. 编辑形态 = **结构化「详情模块」编辑器**（非纯富文本）；每个模块内部可用富文本。
> 2. 数据模型 = **新增结构化详情表**，保留 `description` 作为「商品简介」。
> 3. 多语言 = **每种语言独立编辑** + 一键复制到其它语言。
> 4. 规格参数 = 管理端自由录入 **Key-Value**，店铺端渲染全部 KV。
> 5. 店铺端下半部顺序调整为：**规格参数 → 用户评价 → 商品详情 → 类似推荐**。
> 6. 图片点击放大（灯箱）+ 懒加载；视频模块支持 B 站 / YouTube / 直链 mp4。

## 一、数据模型

### 1.1 `ck_shop_product_detail_block`（商品详情模块）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | varchar(36) | 主键（`ASSIGN_ID`） |
| `product_id` | varchar(36) NOT NULL | 商品ID |
| `language_code` | varchar(10) NOT NULL | 语言代码（zh/en/fr…） |
| `block_type` | varchar(32) NOT NULL | 模块类型，见 1.3 |
| `content` | longtext | 模块内容，**JSON 字符串** |
| `sort_order` | int NOT NULL DEFAULT 0 | 同语言内的展示顺序（升序） |
| `create_by` / `create_time` / `update_by` / `update_time` | 约定列 | 审计字段 |

索引：`KEY idx_block_product_lang (product_id, language_code, sort_order)`

**删除策略：物理删除。** 理由（与 `ck_shop_product_translation` 同类）：
模块是**内容型数据**，不被订单/售后引用，也没有唯一索引；做逻辑删除会让长文本行无限堆积。
详细理由见《商品管理-验证记录》第 17 节对「什么该软删」的界定。

### 1.2 `ck_shop_product_param`（规格参数 KV）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | varchar(36) | 主键 |
| `product_id` | varchar(36) NOT NULL | 商品ID |
| `language_code` | varchar(10) NOT NULL | 语言代码 |
| `param_name` | varchar(100) NOT NULL | 参数名（如「屏幕尺寸」） |
| `param_value` | varchar(500) NOT NULL | 参数值（如「6.7 英寸」） |
| `sort_order` | int NOT NULL DEFAULT 0 | 展示顺序 |
| `create_by` / `create_time` / `update_by` / `update_time` | 约定列 | 审计字段 |

索引：`KEY idx_param_product_lang (product_id, language_code, sort_order)`

**删除策略：物理删除**（同 1.1）。

> 为什么不复用 `ck_shop_product_spec`：Spec 是**销售维度**（决定 SKU 组合与价格），
> 参数是**展示维度**（客户只看不选），两者语义、编辑入口、生命周期都不同。

### 1.3 模块类型与内容 JSON

`content` 统一为 JSON 对象（后端以 `Map<String,Object>` 解析，前端直接使用对象）。
所有文本字段在保存时做长度校验，超限抛明确中文错误，不静默截断。

| blockType | 中文名 | content 结构 |
|-----------|--------|--------------|
| `IMAGE` | 整幅图片 | `{ "url": string, "alt"?: string, "radius"?: number }` — `radius` 单位 px，默认 **0**（无圆角） |
| `IMAGE_GRID` | 多图宫格 | `{ "columns": number \| 1..6（默认 2）, "itemMargin"?: { "top": number, "right": number, "bottom": number, "left": number }, "radius"?: number, "images": [{ "url": string, "alt"?: string }] }`（1–9 张） |
| `IMAGE_TEXT` | 图文（左图右文/右图左文） | `{ "url": string, "title"?: string, "text"?: string, "layout": "left" \| "right", "alt"?: string, "radius"?: number }` — `layout` 表示**图片在左**还是**在右** |
| `TEXT` | 文本段落 | `{ "title"?: string, "text": string }` — `text` 中 `\n` 分段 |
| `RICH_TEXT` | 富文本 | `{ "html": string }` — 保存时白名单清洗，见第五节 |
| `VIDEO` | 视频 | `{ "provider": "bilibili" \| "youtube" \| "file", "url": string, "poster"?: string }` |
| `TITLE` | 小节标题 | `{ "text": string, "sub"?: string }` |
| `DIVIDER` | 分隔线 | `{}` |

字段长度上限（后端校验）：`url`/`poster` ≤ 500，`alt`/`title`/`sub` ≤ 120，`text` ≤ 2000，
`html` ≤ 20000，`paramName` ≤ 100，`paramValue` ≤ 500。

`columns` 允许 **1–6** 的任意整数（编辑器提供 1/2/3 快捷选项 + 自定义输入）；
`radius`、`itemMargin.*` 均为 **0–200 的整数**（越界保存时拒绝，读取时按范围夹取）。

未知 `blockType`：**保存时拒绝**（避免前端升级不同步写出脏数据）；
**读取时跳过**（历史脏数据不能让整页 500）。

### 1.4 模块间距（pitch）——为「长图切割后无缝拼接」而加

**问题**：平面设计常给一张超长图，导出时被切成多张。若模块之间固定留白、图片带圆角，
拼起来就会看到一条条缝，破坏连续性。

**契约**：每个详情模块增加**四方向间距**，存为**表列**（不是 content 字段，便于查询与统一渲染）：

| 列 | 类型 | 默认 | 说明 |
|----|------|------|------|
| `margin_top` | int | 0 | 上间距 px（0–500） |
| `margin_right` | int | 0 | 右间距 px |
| `margin_bottom` | int | 0 | 下间距 px |
| `margin_left` | int | 0 | 左间距 px |

- **默认全部为 0**：模块之间、模块与容器之间**不再有任何默认留白**，长图切割块可以直接贴合。
- 管理端每个模块都可单独调这 4 个值（编辑器提供 0 / 8 / 16 / 24 快捷值 + 自定义输入）。
- 店铺端渲染时把 4 个值以内联 `margin` 应用在模块最外层 `<div>` 上，**不再使用 gap / space-y / mt-* 等统一间距**。
- 图片类模块的 `radius` **默认 0**（无圆角）；只有显式设置时才加圆角。
- **富文本 / 商品简介里的 `<img>` 一律默认无圆角**（不加任何默认 radius）；
  富文本图片属于作者录入内容，不提供模块级圆角设置。
- 想保留文字类模块的可读留白：由运营自己在这些模块上把间距调成 16/24，不在代码里写死。

> **相邻模块的垂直间距按 CSS 常规行为合并（margin collapsing）**：
> 模块是普通块级兄弟元素，实际视觉间距 = `max(上一块 marginBottom, 下一块 marginTop)`，
> 不是两者相加。之所以保留这个行为：默认全 0 时"无缝拼接"最可靠，
> 运营只需要给其中一侧设值即可，不必两头都设。宫格内部每格的 `itemMargin` 在 Grid 里**不会合并**，
> 相邻两图的水平间距 = 左格 right + 右格 left，垂直间距 = 上格 bottom + 下格 top。

> 兼容性：旧数据没有这些值 → 一律按 0 处理；因为默认圆角同时改为 0，**旧商品详情页的图片会从圆角变成直角**，
> 这是本次需求的预期变更（"默认无圆角"），不是回归。

## 二、接口契约

### 2.1 管理端：保存 / 详情

复用现有接口，仅在 DTO/VO 上增加两个集合字段（**不新增接口、不新增权限码**）。

`POST /shop/product/add`、`POST /shop/product/edit`
请求体 `ProductDTO` 增加：

```jsonc
{
  // ...原有字段不变
  "detailBlocks": [
    {
      "id": "可选，前端回填时带上；后端整体替换时不依赖它",
      "languageCode": "zh",
      "blockType": "IMAGE",
      "content": { "url": "https://...", "alt": "正面图", "radius": 0 },
      "sortOrder": 0,
      "marginTop": 0,
      "marginRight": 0,
      "marginBottom": 0,
      "marginLeft": 0
    }
  ],
  "params": [
    { "languageCode": "zh", "paramName": "屏幕尺寸", "paramValue": "6.7 英寸", "sortOrder": 0 }
  ]
}
```

**替换语义（重要）**：

| 提交值 | 后端行为 |
|--------|----------|
| 字段**缺省或 `null`** | 不动现有数据（兼容旧客户端 / 局部保存） |
| `[]`（空数组） | 清空该商品**全部语言**的模块/参数 |
| 非空数组 | 按提交内容**整体替换**该商品全部语言的模块/参数（不逐行 diff） |

> 为什么允许整体替换：模块/参数是纯内容、无外部引用、无唯一索引，
> 整体替换语义最可预测，也避免「新增模块撞唯一键」这类历史坑。
> 保存顺序按数组下标重排 `sortOrder`，前端传的顺序即最终顺序（后端也兜底重排）。

`GET /shop/product/queryById?id=xxx` 返回 `ProductDetailVO`，增加：

```jsonc
{
  // ...原有字段
  "detailBlocks": [ { "id": "...", "languageCode": "zh", "blockType": "TEXT", "content": { "text": "..." }, "sortOrder": 0,
                     "marginTop": 0, "marginRight": 0, "marginBottom": 0, "marginLeft": 0 } ],
  "params": [ { "id": "...", "languageCode": "zh", "paramName": "...", "paramValue": "...", "sortOrder": 0 } ]
}
```

`content` 在接口上**始终是 JSON 对象**（不是字符串）；数据库里才是字符串。
模块的四个 `margin*` 是**独立字段**（不在 content 里），单位 px，缺省按 0。

### 2.2 店铺端：详情

`GET /shop/product/store/detail?id=<id|spuCode>&lang=<zh|en|fr>` 返回 `StoreProductDetailVO`，增加：

```jsonc
{
  // ...原有字段（title/description/specs/combinations/images…）
  "detailBlocks": [ { "blockType": "IMAGE", "content": { "url": "...", "radius": 0 }, "sortOrder": 0,
                      "marginTop": 0, "marginRight": 0, "marginBottom": 0, "marginLeft": 0 } ],
  "params": [ { "paramName": "屏幕尺寸", "paramValue": "6.7 英寸", "sortOrder": 0 } ]
}
```

- 两个集合**只含当前语言最终生效的数据**，已按语言回退（见 2.3），前端不需要再挑语言。
- 不返回 `id`/`languageCode`，店铺端无权也不需要知道内部主键。
- `description` 语义不变：**商品简介**（纯文本或简单 HTML，展示在详情顶部）。

### 2.3 语言回退（店铺端）

对「模块集合」和「参数集合」分别按**语言整体**回退，绝不逐条混排：

1. 请求语言（如 `en`）有任意模块 → 用该语言全部模块；
2. 否则用 `zh` 的全部模块；
3. 否则用「有模块的语言中**语言代码字典序最小**的一个」的全部模块（与实现对齐：保证同一份数据每次返回结果稳定可复现）；
4. 都没有 → 空数组。

参数集合同规则、独立判断（允许「模块回退到中文、参数用英文」）。

## 三、管理端交互契约

### 3.1 页签结构（在现有 `ProductForm` 抽屉内）

`基本信息 → 商品媒体 → 多语言内容 → 商品详情 → 规格参数 → 规格配置 → SKU 组合`

- **多语言内容**：原有标题/副标题/SEO/封面不变；`description` 输入框标题改为
  **「商品简介」**，提示「简短介绍，展示在店铺端详情顶部；长图文请用「商品详情」页签」。
- **商品详情**（新增）：语言页签（与「多语言内容」同一份启用语言列表）。
  - 左侧 = 模块列表编辑器；右侧 = **实时预览**（同一份响应式数据，无需保存即可见）。
  - 模块操作：新增（弹出类型选择）、编辑、上移/下移、删除（二次确认）、拖拽排序。
  - **每个模块的展开区提供「模块间距」**：上 / 右 / 下 / 左 4 个数字输入（0–500px，默认 0），
    旁边给 0 / 8 / 16 / 24 快捷值；这是模块级的布局属性，与 content 无关。
  - **图片类模块（`IMAGE` / `IMAGE_GRID` / `IMAGE_TEXT`）提供「图片圆角」**：0–200px，**默认 0**。
  - **多图宫格额外提供**：列数（快捷 1 / 2 / 3 + 自定义 1–6）、图片间距（上 / 右 / 下 / 左，0–200px，默认 0）。
  - 顶部提供「复制到其它语言」：把当前语言的模块结构 + 内容 + 间距/圆角一起复制（覆盖前二次确认）。
  - 预览顶部提供设备切换：`桌面 (100%)` / `移动 (390px)`；预览区可滚动。
- **规格参数**（新增）：语言页签 + KV 行编辑（参数名、参数值、上移/下移、删除、新增）。
  - 提供「从规格配置生成」：把当前 `formData.specs` 的「规格名 / 可选值」追加为 KV（不覆盖已有行，重复名字跳过），
    让运营少打字；生成后仍可自由改。
  - 提供「复制到其它语言」。

### 3.2 实时预览的保真要求

预览必须使用与店铺端**同一份渲染规则**（模块类型 → 视觉结构、图片比例、**模块间距、图片圆角、
宫格列数与宫格图片间距**、视频嵌入方式）。
实现上允许两份组件代码（两个工程不能共享构建），但**结构、类语义、间距节奏必须一致**，
且预览区宽度按 390px / 桌面内容列（约 880px）模拟，避免"预览好看、店铺端错位"。

预览内容 = 规格参数（当前语言）+ 商品详情（简介 + 模块），按店铺端真实顺序自上而下排列。
只读模式下（`formDisabled`）不显示编辑按钮，仍显示预览。

### 3.3 校验（提交前，前端拦截并切到对应页签）

- 图片类模块必须有 `url`；`IMAGE_GRID` 至少 1 张；
- `TEXT`/`RICH_TEXT` 不能全空（去标签后为空视为空）；
- `VIDEO`：`provider=file` 时 url 必须以 `http(s)://` 或 `/` 开头；B 站/YouTube 能从 URL 解析出 id；
- `params`：参数名、参数值都必填（任一行留空 → 拦下并聚焦）；
- 模块/参数数量上限：每种语言 ≤ 50 个模块、≤ 100 条参数（防止一次提交过大）；
- **布局数值范围**：`margin*` 0–500 整数、`radius` 0–200 整数、`columns` 1–6 整数、
  `itemMargin.*` 0–200 整数；非法值拦下并提示（后端也会拒绝，双重保险）。

## 四、店铺端渲染契约

### 4.1 下半部区块顺序（本次调整）

`规格参数 → 用户评价 → 商品详情 → 类似推荐`

锚点导航（吸顶 chips）同步按此顺序生成，且**只对有数据的区块生成锚点**（沿用现有规则）。

### 4.2 各区块规则

| 区块 | 渲染规则 |
|------|----------|
| 规格参数 | `params` 非空 → 按 KV 渲染（`dt` 参数名 / `dd` 参数值，两列自适应，长值换行）；`params` 为空且历史自动行（spuCode/categoryName 等）存在 → 沿用旧渲染，保证老商品不变空 |
| 用户评价 | 不变（真实汇总，0 值不渲染） |
| 商品详情 | 顶部渲染 `description`（简介，若有）；下方渲染 `detailBlocks`；**无模块但有 description** → 按旧逻辑渲染 description HTML（老商品兼容）；两者都空 → 显示「暂无商品描述」 |
| 类似推荐 | 不变 |

### 4.3 模块渲染细则

- **模块外层间距**：每个模块最外层 `<div>` 用内联 `margin: <top>px <right>px <bottom>px <left>px`
  渲染四个 `margin*` 字段（默认 0）；**容器不得再加 `space-y-*` / `gap` / `mt-*` 之类的统一间距**，
  否则默认 0 也会被撑开，长图切割块就拼不严。
- **图片**：`width:100%`、`height:auto`、**`border-radius` 取 `content.radius`（缺省 0，即直角）**、
  `loading="lazy"`、`decoding="async"`，点击打开灯箱。**不要再用组件默认圆角类**（如 `rounded-[...]`），
  否则运营无法通过"默认 0"实现无缝拼图。
- **灯箱**：遮罩 + 图片居中 + 左右切换 + 关闭；支持 `Esc` / `←` / `→`；打开时锁定 body 滚动；移动端可点遮罩关闭。
  多图模块的图片集合作为灯箱的浏览序列。
- **多图宫格**：列数取 `content.columns`（1–6，缺省 2），用 CSS Grid `repeat(columns, minmax(0, 1fr))` 均分；
  每张图片作为一格，**按 `content.itemMargin` 给每格加 margin**（上/右/下/左，缺省 0）——
  即相邻两图的水平间距 = 左格 right + 右格 left，垂直间距 = 上格 bottom + 下格 top；
  列数为 1、itemMargin 全 0、radius 0 时，多张图**上下紧贴**，用于长图切割后的连续展示。
  移动端不横向溢出；图片按容器宽度自适应高度（不要强制 1:1，否则长图切割块会被裁剪）。
- **图文**：≥768px 左右两栏（图 45%），<768px 上下堆叠（图在上），`layout` 只影响桌面端顺序；
  图片圆角取 `content.radius`（缺省 0）。
- **文本**：按 `\n` 分段；标题用 `h3` 级别样式。
- **富文本**：渲染前清洗（见第五节），容器内样式收敛（图片自适应、链接品牌色、表格可横向滚动）。
- **视频**：
  - `bilibili`：`https://player.bilibili.com/player.html?bvid=<BV号>&page=1&high_quality=1&danmaku=0&autoplay=0`，
    iframe 16:9 自适应、`allowfullscreen`、`referrerpolicy="no-referrer"`、`loading="lazy"`；
  - `youtube`：`https://www.youtube-nocookie.com/embed/<id>`，参数同上，**不加 autoplay**；
  - `file`：原生 `<video controls preload="metadata" playsinline>` + 可选 `poster`。
  - 解析不出 id 时整块不渲染（不输出坏 iframe）。
- **标题 / 分隔线**：纯装饰，无数据依赖。

> 无缝长图的推荐用法（写进运营说明）：把长图切成 N 段 → 每段一个 `IMAGE` 模块，
> 模块间距 4 个值全为 0、圆角为 0；或用一个 `IMAGE_GRID`，列数 1、图片间距全 0、圆角 0。

### 4.4 无障碍与性能

- 灯箱按钮有 `aria-label`，焦点可见；关闭后焦点回到触发图片；
- 图片必须有 `alt`（缺省用商品标题 + 序号）；
- 视频 iframe 有 `title`；
- 详情模块不引入第三方脚本、不阻塞首屏（图片懒加载、iframe 懒加载）。

## 五、富文本安全（双层清洗）

1. **保存时（后端）**：`RICH_TEXT` 的 `html` 走白名单清洗：
   - 允许标签：`p br strong b em i u s ul ol li h2 h3 h4 blockquote a img span div table thead tbody tr td th hr`
   - 允许属性：`a[href,title,target,rel]`、`img[src,alt,width,height]`、`td/th[colspan,rowspan]`
   - 强制：`a` 加 `rel="noopener noreferrer"`、外链 `target="_blank"`；`img` 只允许 `http(s)://` 或 `/` 开头
   - 移除：`script style iframe object embed form input link meta`、所有 `on*` 事件、`javascript:`/`data:` 协议
2. **渲染时（店铺端 + 管理端预览）**：再过一遍同一套白名单（前端实现），
   防止「历史脏数据 / 绕过接口直接写库」。

> 说明：不引入新的第三方清洗库（本机 Maven/npm 取包受限，且新增依赖会破坏现有构建链路），
> 因此两层都用「标签/属性白名单 + 协议白名单」实现，并在文档中标注其局限：
> 这是**收敛风险**而非密码学级保证；富文本的写入入口只有管理端登录用户。

## 六、兼容、回退与灰度

- 老商品没有模块/参数：店铺端表现与改造前**完全一致**（详情渲染 description，规格参数用自动行）。
- 新增布局字段（`margin*` / `radius` / `itemMargin` / 自定义 `columns`）缺省即 0 或 2，
  旧数据不需要迁移；但**详情模块图片默认圆角由"有"改为"无"**，旧详情页的图片会显示为直角，
  这是本次需求的预期变更（默认无圆角），在验证记录里单独标注。
- 前端提交 `null` 不清空数据（见 2.1），避免旧版管理端把新数据抹掉。
- 新增表不修改任何既有列，迁移脚本可重复执行，**不删除、不改写既有数据**；
  本次新增的是 `ALTER TABLE ADD COLUMN`，只加列、不动行。
- 管理端预览是纯本地渲染，不新增后端接口，因此**不产生额外请求**。
