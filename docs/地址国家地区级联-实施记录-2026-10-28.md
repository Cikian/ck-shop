## 二、三个关键设计决策（后续改动请勿破坏）

1. **编码 + 文字双轨**。`country_code`/`province_code`/`city_id` 是权威码（校验、统计、运费分区、物流对接）；
   `province`/`city`/`district`/`country_name` 是**下单那一刻的当地语言快照**。
   地区数据以后怎么变，历史地址都不会跟着变。
2. **落库只存当地语言，译文不落库**。界面要哪种语言，是用 code 反查 `translations` 现算的。
   理由：同一地址可能被中文、法语、泰语用户分别查看，落库只能选一种，落谁都会错。
3. **`fullAddress` 按有无国家分叉**：有国家 → 国际面单格式（逗号分隔、含国家段、**相邻同名去重**，
   曼谷这种"省=市"只出现一次）；无国家（老数据）→ 原 `joinAddress()` 连一个标点都不改。

## 四、这轮踩过的坑（按踩坑代价排序）

0. **页面/布局组件的模板根节点前不能有 HTML 注释（dev 模式下会变成"多根节点"，切语言直接白屏）**。
   Vue 3 在 **dev 构建下保留模板注释**，所以
   ```vue
   <template>
     <!-- 一段说明 -->      ← 这是第 1 个根节点
     <div>...</div>        ← 这是第 2 个
   </template>
   ```
   实际上是一个 **fragment**。Nuxt 启动时会警告
   `` `<x>` does not have a single root node and will cause errors when navigating between routes ``，
   而"切换语言"正是一次**路由间导航**（`router.push(switchLocalePath(code))`）：
   组件无法被 patch，页面内容直接渲染成空。
   **生产构建会剥掉注释，所以只在 dev 下复现** —— 这也是为什么我第一次用生产构建验不出来。
   已修：`app/app.vue`、`app/layouts/auth-split.vue`、`app/pages/profile.vue` 三处把根注释挪进了根元素内部。
   （其余 16 个组件也有同样写法，但它们是普通组件、不是路由组件，不受此限制，暂不动。）

1. **下拉浮层不能用 `position: fixed`（在 UModal 里会整块消失）**。
   `UModal` 默认 `scrollable=false` 时内容容器带 `-translate-x-1/2 -translate-y-1/2`，
   **有 transform 的祖先会成为 fixed 后代的包含块** —— 此时用视口坐标
   （`getBoundingClientRect()`）算出来的 `top/left` 会被当成相对那个容器的偏移，
   而且容器有 `overflow-hidden`，浮层直接被裁到看不见，现象是"点了没反应"。
   正确做法：浮层用 `absolute` 定位在字段容器里，坐标**只依赖两个 rect 的差值**
   （触发器 vs 滚动容器）—— 同一个 transform 同时作用于两者，差值不变。
   顺带好处：浮层与触发器在同一滚动容器内，滚动时自动跟随，不需要监听 scroll。
2. **`maxHeight` 不能有硬下限**。曾经写 `Math.max(160, 可用空间)`，向上展开时上方只剩 110px
   也硬撑到 160 → 顶部溢出滚动容器被裁 → **搜索框整行看不见**。现在最小 96px，空间不够就压扁。
3. **`cities.state_code` 存的是 `states.iso2`，不是 `iso3166_2`**。
   曼谷在 `cities` 里是 `'10'`，在 `states` 里是 `'TH-10'`。任何"按省码过滤城市"的 SQL 直接写
   `cities.state_code = provinceCode` 会**永远查不到数据且不报错**。
   正确做法：先把 `provinceCode` 解析成 `states.id`，再按 `cities.state_id` 过滤。
4. **`@IgnoreAuth` 必须标在方法上，且方法 mapping 要显式写 `value()`**。
   `IgnoreAuthPostProcessor` 只扫方法级注解 + mapping 的 `value()`，类上写注解、或写成 `@GetMapping` 无参数都不生效。
5. **改了代码但接口仍 401，先怀疑"跑的是旧进程"**。`mvn compile` 只更新 `target/classes`，
   运行中的 JVM 不重启就不生效（本项目没开 devtools）。判断方法：比对 JVM `StartTime` 与 class 文件时间。
6. **大表不能走 MCP**（`max_allowed_packet` 4MB），
   服务端 `LOAD DATA INFILE` 又被空的 `secure_file_priv` 禁掉 → 只能 `mysql.exe --local-infile`。
7. **重灌地区数据会连索引一起丢**（整表 DROP+CREATE），所以 `post-load-index.sql` 是必跑步骤，
   漏了城市搜索会从 5ms 退化到 495ms。
8. **`cities` 混了多个行政层级**：不过滤 `type IN ('city','municipality','town','adm2')` 的话，
   `adm1` 省级记录、`village`、`section` 会混进"城市"下拉（15.2 万条里只有 9.7 万条该出现）。
9. **`translations` 上写 `OR EXISTS` 子查询会炸性能**：对每个 city 做一次依赖子查询 = 495ms。
   拆成"名称查询 + 译文前缀查询"两段再合并 → 5–17ms。
10. **dev server 只绑 IPv6**：本机 nuxt dev 监听 `::1`，用 `127.0.0.1` 访问会得到
    `426 Upgrade Required`（看着像服务没起，其实起了）。调试一律用 `localhost`。
11. **端口归属要确认**：本机 3000 上是**另一个项目**（single-spa 微前端壳，控制台报
    "You have to install axios"），ck-shop 的 dev server 在 **6001**。自动化脚本探测前先验证
    "这个端口返回的 HTML 是不是目标项目"，否则会对着别人的应用下一堆错误结论。

### 下拉浮层的验收方式（以后改这块请照做）

这是**唯一**一次靠自动化浏览器测量才定性的问题，光看构建通过没有任何意义。
探针做法（临时脚本，用完即删）：

1. 用生产构建起一个实例（`node .output/server/index.mjs`），`NUXT_API_BASE_URL` 指向新后端；
2. Edge 以 `--headless=new --remote-debugging-port=9445` 启动，用 `ws` 手写极简 CDP 客户端；
3. 登录态直接用 Redis 里 `prefix_user_token:*` 的真实 token 塞进 `access-token` cookie
   （`/sys/login` 已被验证码拦住，别硬闯）；
4. 打开 `/zh/address` → 点"新增地址" → 点国家触发器，然后**断言几何**：
   浮层已渲染 / 未被滚动容器裁掉 / 宽 ≥ 380 / 搜索框可见 / `scrollbar-width: none` /
   下方字段位置在点击前后不变。
   实测 8/8 通过（1280×900：浮层 380×314，落在容器 180–710 之内）。

## 六、追加修正（2026-10-28 晚）

1. **手填国家时省/州这一级被整块隐藏（已修）**。
   `showStateLevel` 原本有 `if (countryMode === 'manual') return false`，而 `toggleCountryManual()`
   同时把 `stateMode` 置成了 `'manual'` —— 结果"模式是手填、但渲染被 v-if 干掉"，
   用户手填国家后只剩「国家 + 城市」两栏，省/州连输入框都没有。
   这与契约 §5.2"每一级都要有手动输入兜底"冲突，而且很多国家面单必须写州/省。
   **修法**：删掉那条 early return（`!countryCode` 分支本来就 return true），
   手动国家时省/州自然落到文本框分支；"从列表选择"链接自带 `modelValue.countryCode` 守卫，
   此时不渲染，不会出现"点回去是个空列表"的死路。真浏览器验证：国家/省州/城市三栏均为可填文本框。
2. **新增/编辑地址弹窗加宽一档**：`sm:max-w-xl`（桌面约 512px → 576px），移动端与删除确认弹窗不变。
3. **三级改成"带搜索的输入框"，取消"列表 / 手动"模式切换**（用户定的规则）。
   旧设计的问题：模式切换是隐藏状态，用户不知道自己在哪一档；切换会清空已选编码，代价大；
   而且"手动国家"那条分支还曾经把省/州整级藏掉（见上一条）。
   **新规则**（三条，缺一不可）：
   - **国家：只能从列表点选**，可搜索，但搜不到时**只提示、不给"使用输入值"入口**。
     理由：`country_code` 是整条地址的根（国际区号、邮编正则、运费分区、物流对接全靠它），
     退化成自由文本等于把这些能力全丢掉，而 250 国已覆盖所有实际国家。
   - **省/州、城市：有结果必须点选；只有"搜不到"时才出现 `使用 "{输入值}"`**，
     点了才落成手填（编码清空 + 写文字 + 出现「手填」徽标）。有结果却想直接存文字？不给。
   - **输入了文字但没点选就离开（失焦/Esc/点外部）→ 回滚成上次选中的名字**，
     绝不静默落文字。这是本次改造的安全线：否则 `Bangkkok` 这种拼写错误会被静默存成
     一条无编码、无当地语言的地址，用户还以为选好了。
   实现上：每级只有 5 个会写模型的入口（3 个点选 + 2 个「使用输入值」），
   打字只改 query、不碰 model。旧浮层里的搜索框已删除（输入框本身就是搜索框）。
   真浏览器验收 12/12（国家无入口 / 省州有入口且落手填带徽标 / 有结果时无入口 /
   未点选离开回滚 / 旧模式切换链接不存在）。
4. **弹窗内一律不出现滚动条 + 宽高加大 + 下拉按整行对齐**（2026-10-29）。
   - 滚动条：`UModal` 的 body 是 `overflow-y-auto`，内容一高就出现竖条（用户截图右侧那条）。
     按"弹窗内不要出现滚动条"的要求，给 `:ui` 的 `body` 加项目既有的 `.no-scrollbar`：
     **滚动能力保留、滚动条不画**。下拉列表本来就用 `.no-scrollbar`。
   - 宽高：`sm:max-w-xl` → `sm:max-w-2xl`（576 → 672px），
     高度上限 `100dvh-2rem` → `100dvh-1rem`（`sm` 下 `100dvh-1.5rem`），把视口高度吃满。
     实测 649×734 视口下弹窗 617×642、**内容不再溢出**（overflow 0px，根本不需要滚动）；
     1280×900 下 672×642。
   - 整行对齐：滚动条隐藏后"半截行"很刺眼（截图里最后一行只露半个字）。
     浮层高度压到 `OPTION_ROW_HEIGHT` 的整数倍，并把选项行高固定成 `h-9`（36px）。
     ⚠️ **不要改回"量第一个 li 的高度"**：城市列表是远程回来的，第一次 `measurePanel()` 时
     `li` 还不存在（量到 0 → 跳过对齐），数据到了也没有可靠的重量时机 —— 实测这么写完全不生效
     （面板仍是 `max-height: 302.375px`）。固定行高后对齐变成纯算术，不依赖渲染时序。
     实测浮层高 296px = 8 行 × 36 + 8(padding)，余 0。
   验收：真浏览器 8/8 ×2 视口（无可见滚动条 / 无滚动条占位 / 宽度符合 / 不溢出 / 整行对齐）。
5. **中国（CN）的城市层类型规则修正**（2026-10-29，用户反馈"直辖市下面全是乡镇、省份少了很多市"）。
   根因**不是数据源缺数据**，而是我们用了一套"通用国家"的 type 白名单 `city/municipality/town/adm2`：
   - 中国的地级市是 `type='prefecture'`（该 type 全球只有 CN 与 GN 有），被白名单整体排除 →
     省份里只剩县级市与乡镇，看起来"少了很多市"；
   - `town` 在中国是**乡镇**（杨柳青/北仓/赤土…），被白名单放进来了 → 直辖市下全是乡镇；
   - 上游还有同名跨级重复（"承德"与"承德地区"、"中山"两条），造成下拉里出现两个"辛集"。
   **修法**：`ShopRegionMapper.xml` 新增 `<sql id="cityTypeFilter">`，三处城市查询共用：
   - CN 且该 state 是 `municipality`（北京/天津/上海/重庆）→ `type='section'`（16 个区：和平/南开/河西…）；
   - CN 其它（省/自治区）→ `type='prefecture'`（河北 11 个地级市、广东 21 个）；
   - 其它国家 → 原白名单不变；
   - 追加 `AND (country_code <> 'CN' OR level IS NOT NULL)` 去上游同名重复（实测只命中重复行：
     省 279→273、自治区 56→55、直辖市 70→70，不误伤）。
   实测：天津 16 区、河北 11 市（无重复）、广东 21 市；泰国 16 条、美国 198 条**零变化**。
   浏览器 7/7 通过。**副作用**：改造前存下的 CN 地址若 city_id 属于乡镇（town），编辑时校验会失败
   （旧规则把乡镇当城市）；本店不做国内生意且线上无存量，接受。
   ⚠️ 另有一处**上游译文缺陷**（与本条无关）：`translations` 里广州译成"广"、郑州译成"郑"，
   属于数据质量问题，需要时用别名补丁表覆盖，不要改上游表。
6. **东南亚数据审计与修正**（2026-10-29）。用户要求"确保其他国家不出现缺数据、层级混乱"，逐项审计后修了三处：

   **审计结论（11 国）**：孤儿 0、无州城市 0；问题集中在两类：

   | 问题 | 实际情况 | 处理 |
   |---|---|---|
   | 菲律宾 states 混了两个层级 | 101 = 82 省 + **18 个大区(region)** + 1 特殊区；11 个大区下还直接挂了 167 个城市 | 隐藏"有下级省份的 region"，**保留 NCR**（马尼拉大都会没有省、14 市直挂），PH 84 州 |
   | 印尼 states 混入宏观地理区 | 45 = 36 省 + **7 个 geographical unit**（Jawa/Kalimantan…，0 城市） | 按 type 排除（该 type 全球仅 ID 使用） |
   | 城市同名重复 | 菲律宾 4 组、泰国 3 组（同名同人口各两份） | 按 `(state_id, name, type, population)` 全等去重，保留 id 最小 |

   **为什么不做"隐藏所有空州"**：会让 SI 138/212、UG 89/139、FR 24/124 等合法行政区消失，
   等于用户没法寄到那些地方 —— 空州应降级为手填，不能删。

   **剩余空州（19 个，均为"只有省本身记录"）**：BN 2/4、KH 3/25、LA 7/18、MM 1/15、MY 3/16、
   TH 1/78、TL 2/13。这些省下拉确实没有城市可选（上游只有 `adm1`/`capital` 记录），
   处理方式是**手填兜底**，并新增 i18n `address.cityNoDataHint`
   （"该地区暂无城市数据，请直接输入城市名"）与"没有匹配结果"区分开，避免误导成搜索无果。

   **实现细节**：`cityDedupeFilter` 里**不能用 `<=>`**（NULL 安全等号）——
   MyBatis-Plus 的 SQL 解析器会报 "Failed to process"（实测 500），改成
   `COALESCE(d.population, -1) = COALESCE(c.population, -1)` 才通。
   另外 `stateCode` 只在**列表**接口过滤（`selectStates`），
   `selectStateByCode`/`selectStateByCode` 等校验/回显路径不过滤，
   否则改造前存下的 PH 大区地址会编辑失败。

   **验证**：PH 101→84（NCR 14 市在）、ID 45→38、其余 9 国州数不变；
   San Miguel 重复 2→1；11 国首州均有城市（1–57 条）；CN/TH/US 对照组零变化。
