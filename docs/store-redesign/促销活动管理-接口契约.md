# 促销活动管理 · 接口契约（前后端唯一依据）

> 管理端需要一套「促销活动」管理功能。首页的限时秒杀条就是读这里的活动。
> 本文是前端（admin-client）与后端（ck-server）的**唯一契约**，两边都按本文实现，不要各自发挥。

生成日期：2026-10-14

---

## 0. 需求确认结果（已与用户确认）

| 决策点 | 结论 |
|---|---|
| 范围 | **只做「促销活动」管理**，不做优惠券（券表已建但本期不碰） |
| 活动价 | **两者都支持**：关联商品可手填 `promoPrice`；没填则按活动类型自动算 |
| 秒杀场次 | **不做场次**，一个活动 = 一个时间窗 |
| 店铺隔离 | **按店铺隔离**：活动必须属于某个店铺，选商品时只列该店铺商品 |
| 前台展示 | **多条活动轮流播放**（不是只显示第一条） |
| 附加能力 | 复制活动 / 上下线快捷开关 / 关联商品批量设置 / 冲突检测 / 导入导出 Excel / 前台效果预览 |
| 用户补充 | **秒杀条背景图可自定义**；**活动标题支持多语言**（zh/en/fr） |

## 2. 后台接口（`ck-server`，需登录，路径前缀 `/shop/promotion`）

> ⚠️ **重要**：现有店铺端（免登录）接口原为 `GET /shop/promotion/active`，
> 本次**必须改名为 `GET /shop/promotion/store/active`**，
> 与既有约定 `/shop/product/list`（后台）vs `/shop/product/store/list`（店铺端）保持一致，
> 避免匿名接口和后台 CRUD 混在同一前缀下。
> 改名前台调用方（`nuxt-shop/server/api/promotions/active.get.ts`）由 Lead 同步修改。

|---|---|---|---|---|
| GET | `/shop/promotion/list` | 登录即可 | `PromotionQuery` + `pageNo` + `pageSize` | `Result<IPage<PromotionListVO>>` |
| GET | `/shop/promotion/queryById` | 登录即可 | `id` | `Result<PromotionDTO>` |
| POST | `/shop/promotion/add` | `shop-promotion:add` | `PromotionDTO` | `Result<String>`（**新活动 id**） |
| PUT/POST | `/shop/promotion/edit` | `shop-promotion:edit` | `PromotionDTO` | `Result<String>`（活动 id） |
| PUT/POST | `/shop/promotion/updateStatus` | `shop-promotion:edit` | `id`, `status`(Y/N) | `Result<String>` |
| POST | `/shop/promotion/copy` | `shop-promotion:copy` | `id`, `newCode`(可空) | `Result<String>`（**新活动 id**） |

### 2.2 `PromotionListVO`（列表页）


## 3. 业务规则（后端硬校验 + 前端同步提示）

| 规则 | 说明 |
|---|---|
| 时间窗 | `startTime` 必须**早于** `endTime`，否则报错 |
| 编码唯一 | 同一 `store_id` 下 `code` 唯一（含软删除的也算占用，避免恢复后冲突） |
| 类型必填项 | `SECKILL` → `seckillStock` 必填且 > 0；`PERCENT` → `discountValue` ∈ (0,10)；`DIRECT` → `discountValue` > 0；`FULL_CUT` → `thresholdAmount` > 0 |
| 店铺必填 | `storeId` 必填 |
| 多语言 | 至少一条 `translations`，且必须包含 `zh`（其它语言可缺） |
| 活动价 | `promoPrice` 为空 = 按活动类型自动算，**不是 0 元**，不要把空值当 0 存储 |
| 关联商品 | 允许为空（先建活动后加商品）；不允许同一活动重复关联同一 `product_id` + `sku_id` |
| 商品归属 | 关联的商品必须属于该活动所在店铺（用 `ck_shop_product.sys_org_code` 对应店铺的 `depart_id` 解析，复用既有 `ShopOrgScopeResolver`） |
| 删除 | 软删除：主表 `del_flag=1`，同时清理关联表与翻译表（物理删除关联行即可） |
| 复制 | 见下 |

### 复制活动的语义（`/copy`）

1. 复制主表（**新 id**），`code`：入参 `newCode` 优先，否则 `原code + "-COPY-" + yyyyMMddHHmmss`
2. 复制全部 `translations`
3. 复制全部 `promotion_product`
4. **时间窗原样复制**（运营自己改），**`status` 强制置为 `N`（停用）** —— 复制出来的活动不应直接生效，必须人工确认后启用
5. `title` 增加后缀「(副本)」，方便在列表里区分
6. 返回新活动 id

### Excel 导入导出范围（**明确告知用户**）

- 导出：活动主表字段 + 店铺名 + 类型/状态（带 `@Excel` 注解，`replace` 用中文）
- 导入：**只导入活动主表字段**（编码、类型、名称、时间窗、力度、状态、店铺编码）。多语言明细与关联商品**不参与导入**（Excel 单行无法表达多行明细）—— 这必须在页面上用文字说明，不能让用户以为导入了商品。

## 4. 店铺端接口（免登录，`@IgnoreAuth`）

| Method | Path | 返回 |
|---|---|---|
| GET | `/shop/promotion/store/active` | `Result<List<PromoBriefVO>>` |

- 只返回**进行中**的活动：`status='Y'`、`del_flag=0`、`start_time <= NOW() <= end_time`
- 排序：`sort_order ASC, end_time ASC`
- 上限：**10 条**（前台轮播多条，不能无限）
- 按当前店铺过滤（复用 `StoreResolver`，与 `/shop/product/store/list` 完全一致的方式）

### `PromoBriefVO`

```
id, type,
title, subTitle,        // 按 lang 解析：translation[lang] → translation['zh'] → 主表 title
bgImage,                // 秒杀条背景图，可空
linkUrl,
startTime, endTime,
discountValue, thresholdAmount, seckillStock,
productId,              // 该活动关联的第一个商品（「立即抢购」跳转用），可空
productCount
```

> 现有实现返回的是**单条**语义（前端只取第一条），本次要改成**多条**，
> 且必须带上 `bgImage` 与按语言解析后的 `title`/`subTitle`。
