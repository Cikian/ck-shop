# 店铺端重构 · 后端促销/销量字段清单

> 目标：让店铺端能出现「国内主流电商」必须具备的元素——划线原价、销量、评价、优惠券、秒杀倒计时。
> 结论：**这些元素在当前 `ck-shop` 库里一个都不存在**，必须补。本文给出可直接落地的字段/表/接口清单。

生成日期：2026-10-13 · 依据：`ck-shop` 库实际表结构（16 张 `ck_shop_*` / `sk_shop_*` 表）

---

## 1. P0：商品表冗余字段（改动最小，收益最大）

**为什么用冗余字段而不是实时聚合**：店铺端列表页每页 12 条，若每条都去 join 评价表/订单表算销量，会明显拖慢列表接口。经典做法是**写时累加**（下单/评价时 `UPDATE ... SET sales_count = sales_count + n`），列表直接读列。

### DDL

```sql
ALTER TABLE `ck_shop_product`
  ADD COLUMN `original_price`   DECIMAL(10,2)      NULL      COMMENT '划线原价/市场价, NULL=不展示划线' AFTER `price`,
  ADD COLUMN `sales_count`      INT UNSIGNED       NOT NULL DEFAULT 0 COMMENT '累计销量(仅统计已支付订单)' AFTER `stock`,
  ADD COLUMN `month_sales_count` INT UNSIGNED      NOT NULL DEFAULT 0 COMMENT '近30天销量(用于"月销"与爆款榜)' AFTER `sales_count`,
  ADD COLUMN `review_count`     INT UNSIGNED       NOT NULL DEFAULT 0 COMMENT '评价总数' AFTER `month_sales_count`,
  ADD COLUMN `rating_avg`       DECIMAL(2,1)       NOT NULL DEFAULT 5.0 COMMENT '平均评分 0.0-5.0' AFTER `review_count`,
  ADD COLUMN `favorite_count`   INT UNSIGNED       NOT NULL DEFAULT 0 COMMENT '收藏数' AFTER `rating_avg`,
  ADD COLUMN `view_count`       INT UNSIGNED       NOT NULL DEFAULT 0 COMMENT '浏览量' AFTER `favorite_count`,
  ADD COLUMN `free_shipping`    TINYINT(1)         NOT NULL DEFAULT 0 COMMENT '是否包邮' AFTER `view_count`,
  ADD COLUMN `listed_at`        DATETIME           NULL      COMMENT '上架时间(做"新品"排序, 比 create_time 准)' AFTER `free_shipping`;
```

### 字段与 UI 的对应关系

| 字段 | 支撑的 UI | 展示规则建议 |
|---|---|---|
| `original_price` | 划线价 `~~¥5,999~~` | 仅当 `original_price > price` 时显示；否则不显示（**绝不显示 0 或假值**） |
| `sales_count` | 「已售 1.2万件」 | `0` → **整行不渲染**；≥10000 显示「1.2万件」 |
| `month_sales_count` | 「月销 856」/ 爆款榜排序 | `0` → 不渲染；榜单用 `ORDER BY month_sales_count DESC` |
| `review_count` + `rating_avg` | 「4.9 分 · 1286 条评价」 | 两者都为 0 → 不渲染 |
| `favorite_count` | 「1.2 万人收藏」 | `0` → 不渲染 |
| `view_count` | 「浏览 3.4 万」 | 一般只用于后台，店铺端可选 |
| `free_shipping` | 「包邮」绿色标签 | `true` 才显示 |
| `listed_at` | 「新品」排序、`NEW` 自动打标 | 为空时回退 `create_time` |

> 💡 **关键原则（延续项目既有约定）**：所有统计字段为 0 / NULL 时，**前端整个元素不渲染**，而不是显示 `0 件` 或兜底假数据。这正是项目文档里「删除编造促销和假评价」的同一条原则。

## 2. P1：促销体系（新表）

需要支撑：直降、折扣、满减、限时秒杀（含倒计时）、优惠券。

### 2.1 促销活动主表

```sql
CREATE TABLE `ck_shop_promotion` (
  `id`            VARCHAR(36)  NOT NULL COMMENT '主键',
  `store_id`      VARCHAR(36)  NOT NULL COMMENT '所属店铺(多店铺隔离)',
  `code`          VARCHAR(50)  NOT NULL COMMENT '活动编码',
  `type`          VARCHAR(20)  NOT NULL COMMENT 'DIRECT-直降 / PERCENT-折扣 / FULL_CUT-满减 / SECKILL-秒杀',
  `title`         VARCHAR(100) NOT NULL COMMENT '活动名称,如"限时秒杀"',
  `sort_order`    INT          NOT NULL DEFAULT 0 COMMENT '优先级(同商品多活动时的取值顺序)',
  `start_time`    DATETIME     NOT NULL COMMENT '开始时间',
  `end_time`      DATETIME     NOT NULL COMMENT '结束时间(倒计时依据)',
  `discount_value` DECIMAL(10,2) NULL    COMMENT '直降金额 或 折扣率(如8.50=8.5折)',
  `threshold_amount` DECIMAL(10,2) NULL  COMMENT '满减门槛(FULL_CUT用)',
  `seckill_stock` INT UNSIGNED NULL      COMMENT '秒杀限量(SECKILL用)',
  `limit_per_user` INT UNSIGNED NULL     COMMENT '每人限购(SECKILL用)',
  `status`        VARCHAR(2)   NOT NULL DEFAULT 'Y' COMMENT 'Y-启用 N-停用',
  `del_flag`      TINYINT(1)   NOT NULL DEFAULT 0,
  `create_by`     VARCHAR(50)  NULL,
  `create_time`   DATETIME     NULL,
  `update_by`     VARCHAR(50)  NULL,
  `update_time`   DATETIME     NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_promotion_code` (`store_id`, `code`),
  KEY `idx_promotion_time` (`store_id`, `status`, `start_time`, `end_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='促销活动';
```

### 2.2 活动-商品关联

```sql
CREATE TABLE `ck_shop_promotion_product` (
```

## 3. P2：评价体系（新表）

> 评价是「国内电商感」权重最高的元素之一，但**必须真实**——刷评/假评分在法律和口碑上都是雷。建议排期在订单模块之后。

```sql
CREATE TABLE `ck_shop_product_review` (
  `id`            VARCHAR(36) NOT NULL,
  `store_id`      VARCHAR(36) NOT NULL,
  `product_id`    VARCHAR(36) NOT NULL,
  `sku_id`        VARCHAR(36) NULL,
  `order_id`      VARCHAR(36) NOT NULL COMMENT '必须来自真实订单',
  `user_id`       VARCHAR(36) NOT NULL,
  `rating`        TINYINT     NOT NULL COMMENT '1-5 星',
  `content`       TEXT        NULL     COMMENT '评价内容',
  `images`        JSON        NULL     COMMENT '晒图URL数组',
  `spec_desc`     VARCHAR(255) NULL    COMMENT '购买规格描述,如"黑色 256G"',
  `is_anonymous`  TINYINT(1)  NOT NULL DEFAULT 0,
  `is_top`        TINYINT(1)  NOT NULL DEFAULT 0 COMMENT '是否置顶',
  `reply_content` TEXT        NULL     COMMENT '商家回复',
  `status`        VARCHAR(2)  NOT NULL DEFAULT 'Y' COMMENT 'Y-显示 N-隐藏',
  `del_flag`      TINYINT(1)  NOT NULL DEFAULT 0,
  `create_by`   VARCHAR(50) NULL, `create_time` DATETIME NULL,
  `update_by`   VARCHAR(50) NULL, `update_time` DATETIME NULL,
  PRIMARY KEY (`id`),
  KEY `idx_review_product` (`product_id`, `status`, `create_time`),
  UNIQUE KEY `uk_review_order_user` (`order_id`, `user_id`, `product_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品评价';
```

> `ck_shop_product.review_count` / `rating_avg` 由评价写入时累加更新，不在列表接口实时聚合。

## 4. 服务标签：复用现有 tag 体系，**不新增字段**

`FAST`(现货速发) / `TOP`(品质优选) 已经在库。若还需要「七天无理由」「正品保证」「全国联保」这类**全店统一**的服务承诺：

- **方案 A（推荐）**：在 `ck_shop_store.theme_config` 里配一个 `servicePromises` 数组，全店共用，不碰数据库结构；
- **方案 B**：往 `ck_shop_tag` 加 code（`RETURN7` / `GENUINE` / `WARRANTY`），挂到商品上。**缺点是冗余**——这三个标签是店铺级的，不是商品级的。

`ck_shop_store.theme_config` 现在是 **NULL**——这就是「多店铺各自换主题」目前做不到的原因。建议定义如下结构（版本化，向前兼容）：

```json
  "brand": {
    "name": "极光商城",
    "logoUrl": "https://.../logo.svg",
    "faviconUrl": "https://.../favicon.ico"
  },
  "palette": {
    "primary": "#FF4D6D",
    "primaryHover": "#E63E5C",
    "accent": "#FFD54A",
    "background": "#FFF6F2",
    "surface": "#FFFFFF",
    "text": "#1F1A1C",
    "textMuted": "#8A8189",
    "border": "#F2E4E6",
    "price": "#FF4D6D",
    "success": "#22C55E",
    "danger": "#EF4444"
  },
  "shape": {
    "radiusCard": "20px",
    "radiusButton": "999px",
    "radiusInput": "12px"
  },
  "typography": {
    "fontFamily": "MiSans, 'PingFang SC', 'Microsoft YaHei', sans-serif",
    "headingWeight": 800,
    "priceWeight": 900
  },
  "home": {
    "sectionOrder": ["hero", "promoStrip", "categories", "recommend", "rank", "more"],
    "promoStrip": { "enabled": true, "text": "新用户首单立减 30 元" },
    "servicePromises": ["正品保证", "极速发货", "七天无理由", "全国联保"]
  },

    "showSalesCount": false,
    "showReview": false,
    "showCoupon": false,
    "showCountdown": false,
    "showOriginalPrice": false
  }
}
```

> 🔑 `features` 开关是**通用性的核心**：
> 新店铺刚上线、数据都是空的时候，把开关全关 → 页面自动退化成「干净的、没有任何统计元素」的版本，不会满屏 `0`；
> 数据积累起来后逐项打开即可。**同一套前端代码，适应从 0 数据到成熟店铺的全过程。**

店铺端读取路径建议：
1. `server/api/store/theme.get.ts` 读 `ck_shop_store.theme_config`（BFF 缓存 5 分钟）；
2. 在 `app.vue` / plugin 里把 `palette` 写成 CSS 变量挂到 `:root`；
3. `tailwind.css` 的 `@theme` 只留**兜底默认值**（用 `var(--brand-primary, #FF4D6D)` 形式），避免配置缺失时白屏。

## 8. ⚠️ 合规红线（不是可选项）

| 元素 | 风险 | 要求 |
|---|---|---|
| **划线原价** `original_price` | 《价格法》《禁止价格欺诈行为的规定》：虚构原价属价格欺诈 | 划线价**必须有真实交易记录支撑**。若无法举证，改用「建议零售价」并标注来源，或干脆不显示 |
| **销量** `sales_count` | 《广告法》第 28 条：虚假宣传 | 只能统计**已支付订单**；不得把加购/浏览量当销量展示（`ck_shop_cart_event` 是加购流水，**不能**当销量用） |
| **评价** | 刷单炒信 | 必须 `order_id` 外键约束，一单一评；不得自建评价 |
| **「限时秒杀」倒计时** | 虚构活动时间 | `end_time` 必须来自真实活动配置，不得前端写死 |
| **「已售 N 件」** | 同上 | 宁可显示「近期热销」这类定性标签，也不要编具体数字 |

> 现在效果图里那些 `¥5,999` / `已售 1.2万件` 是**设计占位**，实现时如果字段没上线，对应元素必须整块不渲染。

## 附：本文档的 SQL 复算依据

以下查询可直接复现本文所有结论：

```sql
-- 1. 现有表清单
SELECT TABLE_NAME, TABLE_COMMENT, TABLE_ROWS FROM information_schema.TABLES
WHERE TABLE_SCHEMA='ck-shop' AND TABLE_NAME LIKE 'ck\_shop%' ORDER BY TABLE_NAME;

-- 2. 确认促销/销量/评价字段确实不存在
SELECT TABLE_NAME, COLUMN_NAME FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='ck-shop'
  AND COLUMN_NAME REGEXP 'sales|review|rating|original|coupon|promo|discount|favorite';

-- 3. 确认 tag 已就绪
SELECT t.code, tt.language_code, tt.name FROM ck_shop_tag t
LEFT JOIN ck_shop_tag_translation tt ON tt.tag_id = t.id ORDER BY t.code, tt.language_code;
```

### 10.2 修复的一处不一致

`freeShipping` 最初在 `StoreProductCardVO` 是 `Boolean`、在 `ShopProduct`（详情 VO 的父类）是 `Integer`，同一个字段两个前台接口返回类型不同。已把实体字段统一为 `Boolean`，两个接口现在都返回 JSON `boolean`，`NULL` 归一成 `false`。

### 10.3 本轮重构暴露出的其它后端缺口（建议进 backlog）

| # | 缺口 | 影响的功能 | 建议 |
|---|---|---|---|
| 1 | **没有收藏关系表/接口** | 商品卡片、详情页、购物车、个人中心**四处**都涉及「收藏」，但只能做本地假状态，所以本轮**刻意都没做**（宁可不做，也不放假控件）。注意 `ck_shop_product.favorite_count` 只是**计数**，不是用户×商品关系 | 新增 `ck_shop_user_favorite(user_id, product_id, create_time)` + 增删查接口 |
| 2 | **没有用户资料编辑接口** | 个人中心「账户设置」只能写本地 `userInfo`（与 `useAuth.restoreUser` 同一份 localStorage），换设备就丢 | 补 `PATCH /shop/user/profile` 或代理 JeecgBoot `/sys/user/edit` |
| 3 | **没有订单 / 地址接口** | 个人中心「我的订单 / 我的收藏 / 收货地址」三个面板只能显示真实空态。本轮已**删除**页面里原有的编造数据（`ORD-2024-001`、3 件假收藏、2 条美国地址、「View All」、`$` 金额、"Gold Member" 假会员等级），统计卡数字一律为 0 | 先补订单表与地址表，再补接口 |
| 4 | **购物车明细缺 `freeShipping`** | 结算明细的「运费」行无法判定，只能显示「待计算」 | 购物车明细 VO 带出商品包邮标记，或提供运费规则接口 |
| 5 | **促销接口没有满减门槛字段** | 购物车「凑单进度条」的**唯一**依据是 `thresholdAmount`；后端不给就永远不渲染（这是正确行为，不是 bug） | `/shop/promotion/active` 的 VO 带上 `thresholdAmount` / `discountValue`（BFF 类型已预留这两个可选字段） |

### 10.4 前端已经做的「零数据降级」约定

为了让上面这些缺口**不表现为页面 bug**，店铺端统一遵守：

> 任何统计/促销/评价/优惠字段为 `0` / `null` / `false` / 不存在时，**对应 UI 元素整块不渲染**，
> 且**不得显示 0 或兜底假值**。判断逻辑收敛在 `nuxt-shop/types/shop-product.ts`
> （`resolvePriceView` / `hasSalesStats` / `hasOriginalPrice` / `resolveRating` / `formatCompactCount`），
> 组件只负责渲染，不各写一套。

因此当前真实效果是：**页面比效果图"干净"**——没有假倒计时、没有假销量、没有假划线价、没有假优惠券。数据接上后，这些元素会自动逐一亮起来。
