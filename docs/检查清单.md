# ck-shop 店铺端 / 管理端检查清单

**检查范围**：店铺端 16 个页面、35 个组件、54 个 BFF 接口；管理端商城模块 11 个模块、56 个文件；后端商城 22 个 Controller、19 个 Service。除静态阅读外，我在 3001 的生产构建上实测了首页、商品列表、商品详情、登录页和 390px 移动端，并只读检查了接口与响应头。**未修改任何文件。**

> 说明：3001 跑的是 10-21 16:01 的构建，工作区还有未提交的评价模块改动；涉及评价区/详情页新改动的表现以源码为准，下文标“实测”的仅限该构建可验证的行为。

**总体结论**：工程底子不错——BFF 统一签名/鉴权/错误映射、httpOnly cookie、CSRF、限流、三语 579 个 key 全对齐，SKU/价格/库存和移动端安全区处理都很细。问题主要集中在三块：**支付 Mock 默认开启与回调半提交（资金）**、**后端读接口缺权限码/实体直出（越权与敏感字段）**、以及一批**一眼可见的体验与视觉问题**（品牌占位、主色变绿、对比度不足、404 变 500、管理端默认通过/未保存丢失）。

## 一、P0：先停下手上的事修（资金/安全）

- [x] **P0-1｜Mock 支付默认开启，买家可自助“0 元购”**
  位置：`ck-shop/order/pay/impl/MockPaymentGateway.java:55`（`matchIfMissing=true`）、`order/service/impl/ShopPaymentServiceImpl.java:133`（默认渠道 `MOCK`）、`order/controller/ShopStorePaymentController.java:73`（`/mock-confirm` 无 profile 限制）。
  所有 `application-*.yml`（含 prod/docker/test）都没有 `ck.shop.pay.mock.*` 配置，因此默认就是开启；`prepay` 还允许客户端自己传 `channel=MOCK`。
  影响：任何已登录买家都能先 `prepay` 再 `mock-confirm`，订单直接变已支付并触发库存实扣；默认 HMAC 密钥 `ck-shop-mock-pay-secret` 还可被用来伪造 `/shop/pay/notify/MOCK` 回调。
  建议：`matchIfMissing=false` + `@Profile("dev")`；prod/docker 显式关闭并 `default-channel` 禁止 MOCK；`/mock-confirm` 仅 dev 暴露；渠道白名单排除 MOCK；启动时检测到 mock bean 直接 fail-fast；删除默认密钥，改为环境变量。

- [x] **P0-2｜支付回调异常被吞，去重键把重试路堵死**
  位置：`order/service/impl/ShopPaymentServiceImpl.java:288`（`@Transactional`）、`:317-321`（重复回调直接 ACK）、`:329-334`（catch 后返回 reject）。
  `handleNotify` 在事务内 catch 所有异常：已执行的支付单、订单状态、资金流水、库存扣减会照常提交，形成半完成状态；`ck_shop_payment_notify_log` 的去重行已落库，渠道重推时被当成“重复回调”回成功，半完成状态再也无法自愈。`mockConfirm` 通过 `this.handleNotify` 自调用，内层事务也不经过代理。
  建议：结算逻辑抽独立 bean，用 `REQUIRES_NEW` 包住；异常必须抛出回滚；回调流水改“处理中→成功”两阶段，失败时释放/标记可重试键；结算事务提交后再 ACK；`mockConfirm` 走代理或直接调用结算 bean；notify 入口加限流和 body 大小限制。

## 二、店铺端（顾客侧）

### P1（高优先）

- [x] **S1｜商品不存在时返回 HTTP 500，错误页完全失效**
  位置：`nuxt-shop/app/pages/products/[slug].vue:655-661`。
  实测 `/zh/products/not-exist-xyz` 返回 500 HTML；服务端日志为 `TypeError: tag.props.content.replaceAll is not a function`，发生在 unhead 的 `tags:afterResolve`。页面虽然有 `isNotFound` 分支，但商品为空时仍注册了 `ogTitle/ogImage` 等 SEO 标签，且没有 `setResponseStatus(404)`。
  建议：商品为空时不要注册商品 SEO（或确保所有 `og*` 是确定字符串）；在 SSR 命中 404 时 `setResponseStatus(404)` 并加 `robots: noindex`，或直接 `throw createError({ statusCode: 404 })`。

- [x] **S2｜品牌名是占位符“Nuxt Shop”，并与站点名“Cikian Shop”混用**
  位置：`nuxt-shop/i18n/locales/{zh,en,fr}.json` 的 `shop.brandName`、`app/components/Header.vue:438-448`、`nuxt.config.ts:173`。
  浏览器标题实际是“欢迎来到 Nuxt Shop | Cikian Shop”，页头/页脚/版权全是 Nuxt Shop。Header 注释也承认目前没有获取店铺信息的接口。
  建议：补 `GET /api/store/info`（name/logo/theme），Header、Footer、SEO 统一读店铺信息；接口未就绪时至少回退 `STORE_SITE_NAME`，不要用示例品牌。

- [x] **S3｜Nuxt UI 主色实际解析成绿色，与珊瑚品牌色分裂**
  位置：`nuxt-shop/app.config.ts:22-25` 设置 `primary: 'brand'`，`app/assets/css/tailwind.css:37-50` 定义 `--color-brand-*`。
  运行时实测 `--ui-primary` 为 `oklch(72.3% 0.219 149.579)`（绿色），而不是 `#FF4D6D`。任何使用 Nuxt UI 默认 primary 的组件（toast、开关、复选、下拉选中态、focus ring 等）都会变绿。
  建议：在 `:root` 显式注册 `--ui-color-brand-50..950: var(--color-brand-*)`，或改用 Nuxt UI 能识别的色名并覆盖 `--ui-primary`；改完在浏览器里断言 `getComputedStyle(document.documentElement).getPropertyValue('--ui-primary')` 是珊瑚色。

### P2（中优先）

- [x] **S4｜图片没有响应式管线，首屏图片体积不可控**
  `components/ShopImage.vue:16-25`、`HomeHeroCarousel.vue:45-52`、`StoreProductCard.vue` 都只输出一个 `src`；`width/height` 只影响布局不缩图。首页首屏同时渲染 hero、热销 6 张、主商品流 18 张，至少 25 张原图；56px 缩略图和 800px 主图用同一 URL。
  建议：引入 `@nuxt/image` 或图片 CDN，输出 `srcset/sizes`、WebP/AVIF；hero 首图 preload + `fetchpriority=high`，首行商品 `eager`，其余 `lazy`。

- [x] **S5｜富文本图片被强制 eager，详情图无尺寸导致 CLS**
  `utils/sanitize-html.ts:50,201-210` 的 img 白名单只有 `src/alt/width/height`，会把源 HTML 的 `loading="lazy"`、`decoding="async"` 剥掉；`components/product/DetailSections.vue:218-222`、`ProductDetailBlocks.vue:38-45` 的详情图没有宽高，加载时从 0 高度撑开。
  建议：清洗器给 img 注入 `loading="lazy" decoding="async"`；后端保存图片宽高，详情块用 `aspect-ratio` 预留空间。

- [x] **S6｜评价和“为你推荐”绕过 `useAsyncData`，客户端必重拉且插入造成 CLS**
  `app/pages/products/[slug].vue:430-432,449-451` 用 `watch(immediate)` + `requestFetch`；评价从 0 条变为有数据时插在“规格参数”和“商品详情”之间，长详情页会被整体推下。
  建议：评价改为按 productId 建 key 的 `useAsyncData`；推荐合并为一次请求，避免“分类请求→不足再全站兜底”的串行；若只客户端加载，保留固定高度骨架。

- [x] **S7｜公开接口无缓存，SSR 默认等 10 秒**
  `nuxt.config.ts` 没有 `routeRules`，`server/utils/apiClient.ts:145` 默认超时 10s。首页一次冷访问会打分类、轮播、促销、热销、主商品流 5 个 BFF 读接口；任何一个后端接口卡住，整页 SSR 最长等 10 秒。
  建议：对 `/api/products/**`、`/api/categories`、`/api/home/slide`、`/api/promotions/active` 配 SWR/CDN 缓存和 `Cache-Control`；公开读接口超时降到 2–3s，失败时返回旧缓存或空数据，不要让整页等待。

- [x] **S8｜分类树重复请求，分类页页码不进 URL**
  `Header.vue:452-456` 用 key `store-categories-${locale}`，`categories/[id].vue:120-124` 又用带 `categoryId` 的不同 key 再取一次；分类页 `pageNo` 是本地 ref（`categories/[id].vue:138`），第 2 页刷新/分享/后退都会回到第 1 页。
  建议：分类树收敛到一个全局 key/composable；分类页把 `pageNo` 写进 `route.query` 并作为唯一数据源。

- [x] **S9｜Sitemap 没有动态商品/分类，商品页也没有结构化数据**
  `nuxt.config.ts:140` 只注册了 `@nuxtjs/seo`，仓库里没有 `server/api/__sitemap__/urls.ts` 或自定义 URL source；商品页 `products/[slug].vue:655-661` 只有 title/description/OG，全仓库没有 `useSchemaOrg`。
  建议：增加 sitemap source，按语言分页返回全部在售商品和分类，带 lastmod；商品页输出 `Product/Offer/AggregateRating/BreadcrumbList` JSON-LD。

- [x] **S10｜筛选/分页参数被 canonical 丢弃**
  `products/index.vue:236-245,353-359` 使用 `keyword/categoryId/sortBy/pageNo`，而 Nuxt SEO 默认 canonical 白名单不包含这些参数；所有筛选、排序、分页变体都 canonical 到 `/zh/products`，但页面仍可索引。
  建议：统一参数名或扩展 `seo.canonicalQueryWhitelist`；搜索/筛选页按策略 `noindex` 或 self-canonical，分页页输出独立 canonical 和 prev/next。

- [x] **S11｜`site.url` 默认 localhost 且没有启动保护**
  `nuxt.config.ts:173-178` 在 `STORE_SITE_URL` 缺失时静默回退 `http://localhost:3000`。生产漏配会把全站 canonical、hreflang、sitemap、OG:url 全部指向 localhost，而页面看起来完全正常。
  建议：生产构建时强制要求绝对 `https://` URL，缺失直接抛错；仅 dev 允许 localhost。

- [x] **S12｜页脚 12 个链接和隐私/条款/Cookie 全是不可能点的文本**
  `app/components/SiteFooter.vue:63-73,78-85` 把购物指南、客户服务、关于我们三列 12 个链接以及隐私政策、服务条款、Cookie 政策都渲染成 `<span>`。视觉上它们仍是页脚链接，用户点不动；同时缺少电商合规通常需要的隐私政策、服务条款、营业执照/ICP 等页面。
  建议：没有页面就删掉这些列，或明确标“即将上线”并降低视觉权重；优先补隐私政策、服务条款、退换货/配送说明。

- [x] **S13｜商品列表页出现三层重复分类导航**
  `products/index.vue:55-113` 同时渲染 Header 一级分类、分类筛选 chips、以及“相关搜索”（内容仍是同一批分类名）。用户在 1440px 下会连续看到三行几乎相同的分类入口，筛选区显得很吵；且未选任何条件时“清空筛选”也一直显示。
  建议：只保留一行分类 chips；有关键词时才显示“相关搜索”，或把它改成真正的搜索词建议；无筛选时隐藏/禁用“清空筛选”。

- [x] **S14｜个人中心优惠券/积分固定显示 0，没有“未开通”说明**
  `app/pages/profile.vue:338-346` 把 `shop.profileCoupons`、`shop.profilePoints` 直接写死 0。用户会以为“我没有优惠券/积分”，而不是“功能还没接”。
  建议：接口未就绪时隐藏这两张卡，或显示“暂未开通”；不要用真实的 0 伪装成业务数据。

- [x] **S15｜移动端输入框 13–14px，iOS 聚焦会自动放大页面**
  `Header.vue:203`、`login.vue:119` 等输入框使用 `text-sm`（14px）。iOS Safari 对 `font-size < 16px` 的输入框聚焦时会缩放整个页面，用户每次搜索/登录都要手动缩回。
  建议：移动端输入框统一 `text-[16px]`（或 `@media (max-width: 767px)` 强制 16px），视觉字号可用 `transform` 或内层元素控制。

- [x] **S16｜分类不存在时返回 200 + “共 0 件商品”软 404**
  实测 `/zh/categories/does-not-exist` 返回 HTTP 200，标题是“全部分类”，正文“共 0 件商品 / 暂无商品”。这会让搜索引擎收录空页，也让用户以为分类只是没货。
  建议：分类详情页先校验分类是否存在，不存在时 `setResponseStatus(404)` + noindex，或跳转到分类总览并提示“分类不存在”。

- [x] **S17｜全站对比度不足（实测值）**
  `tailwind.css:70` 的 `--color-muted: #8A8189` 对白底 3.76:1、对奶油底 3.53:1；`--color-brand-500: #FF4D6D` 上的白字只有 3.21:1；`--color-warning-600` 在 warning-50 上 3.07:1。它们大量用于 12–13px 正文和小按钮，低于 WCAG AA 的 4.5:1。
  建议：`--color-muted` 加深到约 `#6B6269`；白字按钮改用 `brand-700` 或更深的品牌色；warning 文案改用 `warning-700`；把对比度检查加入设计 token 的 CI。

### P3（细节/打磨）

- [x] **S18｜首页热销横排移动端没有滚动提示**：`HomeHotRow.vue:8-23` 是横向滚动，390px 下第一张卡只露出约 190px，没有 snap、渐变遮罩或“右滑查看更多”，用户容易以为内容被截断。
- [x] **S19｜分类图标按中文关键词匹配**：`HomeCategoryMenu.vue:191-211` 的规则是 `/包|箱/`、`/鞋|靴/` 等；分类名在 `/en`、`/fr` 本地化后会全部匹配不到，统一退化成 `lucide:tag`。建议后端分类返回 `icon` 字段，或按多语言关键词/分类 code 匹配。
- [x] **S20｜已登录冷启动重复请求**：SSR 的 `auth-seed` 已查 session + cart count，客户端 `plugins/init-auth.client.ts:40` 又 `refreshSession()`，`Header.vue:562-564` 又 `refreshCount()`。建议带 TTL 或直接复用 SSR 播种状态。
- [x] **S21｜首页两个 `/api/products`**：热销 6 条 + 主列表 18 条各请求一次，主列表还剔除热销商品；重叠时用户实际只看到 12/18 件。建议聚合 `/api/home` 或服务端 `excludeIds`。
- [x] **S22｜全量 `@nuxt/ui` CSS**：`tailwind.css:31-35` 全量引入，仅用少数组件；当前构建 CSS 约 245KB（gzip 34KB）。建议加 bundle 分析并按组件裁剪。
- [x] **S23｜详情页两套 scroll rAF 每帧读布局**：`useStickyAside.ts:184-200` 和 `DetailSections.vue:415-421` 各自监听滚动并 `querySelector + getBoundingClientRect`。建议合并调度器，用 IntersectionObserver/缓存元素引用。
- [x] **S24｜移动端页头不显示品牌名**：`Header.vue:19-21` 的 wordmark 是 `hidden sm:inline`，390px 下只剩一个闪电图标；品牌识别度弱，建议保留小号字标或至少 `aria-label`。
- [x] **S25｜Cookie 7 天固定过期、无滑动续期**：`server/utils/authCookie.ts:21-32`。用户第 7 天会突然被登出；建议 token 临近过期时静默续期，或缩短有效期 + refresh token。
- [x] **S26｜购物车数量接受小数并静默截断**：`server/api/cart/items/[id].put.ts:25-40` 只校验 `>=1`，`1.9` 会被 `Math.trunc` 成 1，提示语却说“必须是整数”。建议 `Number.isInteger` 校验并加上限。
- [x] **S27｜BFF 没有安全响应头**：实测响应只有 `X-Robots-Tag / Set-Cookie / X-Powered-By`，没有 CSP、HSTS、X-Frame-Options、Referrer-Policy、X-Content-Type-Options。建议在 Nitro 中间件统一加；至少加 `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`X-Frame-Options: SAMEORIGIN`，并在网关加 HSTS。

## 三、管理端（运营侧）

### P1（高优先）

- [x] **A1｜退款审核默认选中“通过”，打开弹窗点确认就发起真实退款**
  位置：`admin-client/src/views/ck/shop/refund/components/RefundAuditModal.vue:7-8,46-49,87`。
  `decision` 初始值就是 `'approve'`，主按钮文案“通过并提交渠道退款”；没有金额二次确认，`refundable` 查询未完成时也能提交。
  建议：默认不选中任何结果，必须显式选择；点“通过”后再弹一次确认，复述退款单号、订单号、支付单号、申请金额与可退金额；`refundable` 未返回前禁用提交。

- [x] **A2｜运维任务一键批量关单/补单，没有二次确认**
  位置：`order/ShopOrderStats.vue:216-221`、`:606`。
  `batchSize` 默认 200、最高 1000，两个按钮直接 `runTask('close'/'compensate')`，误点会批量改变订单/支付状态，不可撤销。
  建议：执行前 `Modal.confirm` 展示“本次将扫描 N 条、影响范围、不可撤销”；超过 50 条要求二次输入确认；按钮仅对 `shop-store:manage-all` 显示（后端也要求该权限）。

- [x] **A3｜商品表单取消/关闭没有未保存提示**
  位置：`product/components/ProductForm.vue:528-537,1545-1547`；`promotion/components/PromotionModal.vue:96-98`。
  商品表单有 7 个页签、多语言、图集、规格、SKU、详情模块，点“取消”或右上角关闭直接 `visible=false`，所有编辑立即丢失。
  建议：基于表单快照做 dirty 检测，关闭/取消/路由离开统一弹“继续编辑/放弃”；保存成功后清除 dirty。

- [x] **A4｜删除规格/规格值无确认，直接级联删除 SKU 组合**
  位置：`product/components/ProductSpecEditor.vue:42-46,72-76`；级联逻辑 `ProductForm.vue:1083-1089`。
  一次误点会移除整个规格及所有引用它的组合，价格、库存、SKU 编码一起丢。
  建议：`popconfirm` 显示“将删除规格 X，并移除 N 个 SKU 组合”；支持撤销；至少不要无确认直接改本地组合数据。

- [x] **A5｜SKU 不完整组合被静默过滤，后面的校验永远不生效**
  位置：`ProductForm.vue:1411-1416` 先 `filter` 掉缺少规格值的组合，`:1425-1437` 再检查 `incomplete`，此时已无可检查数据。
  运营新增规格或历史数据引用异常时，部分 SKU 会静默消失，价格/库存一起丢。
  建议：去掉前置 filter；逐行校验并定位到“SKU 组合”页签对应行，提示缺少哪一维，禁止保存。

- [x] **A6｜轮播图上传图片不触发自动保存**
  位置：`setting/slideshow/components/SlideEditor.vue:110-116,366-378`。
  页面是 700ms 自动保存，但只有文本/开关/链接绑定了 `@change="scheduleSave"`；`JImageUpload` 只更新 `contents`，没有触发保存。只换图片、不改其它字段时，图片不会落库。
  建议：`JImageUpload` 增加 `@update:value="scheduleSave"`；`onBeforeUnmount` 前 flush 一次保存；保存状态显示“保存中/已保存/失败”。

### P2（中优先）

- [x] **A7｜深色模式下大量硬编码浅色**

### P1（高优先）

- [x] **B1｜发起支付 check-then-create 竞态，双击可产生两张有效支付单**

  `ShopStoreController.java:103` 只校验 `shop-store:edit`，`ShopStoreServiceImpl.java:72` 直接 `updateById(store)`；没有 `checkAccessible`/`resolveWritableOrgCode`。持有该权限的店铺运营可以改任意店铺的 `departId/domain/status`，`delete` 同理。

- [x] **B5｜管理端多个读接口没有权限码**
  `product/controller/ShopProductController.java:72`（list）、`:147`（queryById）、`:157`（skuList）；`promotion/controller/ShopPromotionController.java:119`；`category/controller/ShopCategoryController.java:65`；`tag/controller/ShopTagController.java:64`；`home/controller/SlideshowController.java:193` 都没有 `@RequiresPermissions`。JecgBoot 没有 URL 级权限过滤器，菜单权限不等于 API 权限，任何已登录后台账号都能直接读。
