> 版本：v1　　最后更新：2026-10-30
> 对应迁移脚本：`ck-server/db/ck-shop-analytics.sql`（数据模型，手工执行版·幂等）、
> `ck-server/db/ck-shop-analytics-menu.sql`（菜单与权限）；Flyway 版为
> `V3.9.5_N__shop_analytics.sql` / `V3.9.5_M__shop_analytics_menu.sql`（N/M 为实施时下一个可用序号）。
> 设计依据：本次需求「用户行为分析、统计」；用户已确认的关键决策见 §1.2。

## 1. 需求与交付范围

### 1.1 需求原文（用户提出）

1. 统计各商品的访问量、浏览时间等；
2. 用户来源国家、城市、IP 等；
3. 在管理端能进行的统计分析。

强制要求：① 用户 100% 无感；② 不能影响系统性能。

### 1.2 已确认的关键决策（需求方拍板，不得擅自更改）

| 决策项 | 结论 |
|---|---|
| 采集方案 | **混合：自建核心 + GA4 第三方辅助**。自建管"业务事件漏斗 + 与订单/商品/店铺数据关联 + 管理端统一 + 实时大盘"；GA4 管"流量/来源/设备/通用行为"的通用分析。 |
| 采集范围 | **全行为事件漏斗**：浏览 / 曝光 / 点击 / 加购 / 搜索 / 下单 / 支付。 |
| 时效要求 | **强实时**：秒级在线人数、实时大盘（PV / UV / 核心指标）；漏斗明细按分钟级异步聚合（见 §5.4）。 |
| 地域精度 | **国家 + 省/市 + 城市级，海外同样要城市级**。ip2region 达不到海外城市级，改用 **MaxMind GeoLite2 City（离线 mmdb）**。 |
| 量级 / 基础设施 | 日 PV **< 10 万**，按 **MySQL + Redis 保守设计**，不上 MQ / 时序库，但预留扩展点。 |
| 管理端呈现 | **实时大屏 + 仪表盘 + 积木报表 + 自写 AntD 定制页**，四者都要。 |
| 多店铺口径 | **按 `sys_org_code` 隔离 + 超管全局汇总**（复用 `ShopOrgScopeResolver`）。 |
| 合规（本期） | **Cookie 同意横幅要做**；**GA4 普通接入，不接 Consent Mode**；**IP 脱敏、匿名化先不做**（原始 IP 直接落库）。面向欧盟正式运营前必须补 GDPR（见 §10 风险提示）。 |

> 不做国内市场：不引任何国内统计 SDK / 服务；ip2region 仅因精度不够被替换，与合规无关。

## 2. 总体架构

```
浏览器（nuxt-shop，同源 /api/*）
 ├─ ① GA4 gtag.js ── 流量/来源/设备/通用行为（普通接入，不接 Consent Mode）──▶ Google
 └─ ② 前端轻量 SDK（sendBeacon，只补服务端看不到的行为）──▶ /api/track
                    │
                    ▼
nuxt-shop Nitro BFF
 ├─ server/middleware/analytics.ts   每个请求无感采集（PV/UV/来源/UA/语言/店铺/IP）
 │                                    → 内存队列 → 批量异步写，绝不阻塞响应
 └─ server/api/track.post            收前端事件 → 合并进同一内存队列
                    │（异步 · 批量 · 超时静默丢弃）
                    ▼
ck-server Java（自建核心，org.jeecg.modules.shop.analytics）
 ├─ 采集写入：ck_shop_track_event（append-only，无 del_flag，按天归档）
 ├─ 实时层：Redis（在线人数 / PV / UV），秒级大盘只读 Redis
 ├─ 聚合层：定时任务生成 ck_shop_track_summary（小时/日，多维度）
 ├─ 地域层：GeoLite2 City（mmdb，内存加载）解析 IP → 国家/省/市（原始 IP 落库）
 └─ 查询层：实时大盘 / 趋势 / 漏斗 / 排行 / 地域 / 来源 / 设备 / 明细
                    │
                    ▼
admin-client（管理端）
 ├─ 实时大屏（jimubi-bigscreen）  在线 / PV / UV / 实时订单 / 地域滚动
 ├─ 仪表盘（jimubi-dashboard）    KPI / 趋势 / 漏斗 / 排行
 ├─ 积木报表（jimureport）        明细 / 导出 / 自定义 SQL 报表
 └─ 自写 AntD 页                  精细分析（沿用 ShopOrderStats 风格）
```

**核心原则：能服务端拿到的绝不在客户端埋点。** 下单/支付/加购/收藏等业务表已有的数据，**直接从业务流水取，不重复埋点**（延续项目"真实优先"铁律，避免两套口径打架）。埋点只补业务表没有的行为：曝光、点击、搜索、停留、页面流转。

## 3. 数据模型

### 3.1 表清单

| 表 | 作用 | 关键约束 |
|---|---|---|
| `ck_shop_track_event` | 行为明细（append-only） | **无 `del_flag`**（账本类语义）、按天归档、默认保留 30 天可配 |
| `ck_shop_track_summary` | 多维度小时/日汇总（长期保留） | `uk_summary(stat_time, granularity, org_code, product_id, dim_type, dim_value)` |

### 3.2 `ck_shop_track_event`（行为明细）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | varchar(36) | 主键（雪花） |
| `event_time` | datetime(3) | 事件发生时间（毫秒） |
| `event_name` | varchar(64) | 事件名（§4.1 清单，受控枚举） |
| `session_id` | varchar(64) | 会话 ID（BFF 生成，写 cookie） |
| `visitor_id` | varchar(64) | 匿名访客 ID（BFF 生成随机标识，写 cookie，非登录态也唯一） |
| `user_id` | varchar(36) | 登录用户 ID（可空，登录态才回填） |
| `org_code` | varchar(64) | 店铺归属部门编码（快照，`sys_org_code` 语义） |
| `store_id` | varchar(36) | 店铺 ID（可空，首页/列表可能无店，详情/加购必有） |
| `product_id` | varchar(36) | 商品 ID（商品类事件必填，其余可空） |
| `page_url` | varchar(512) | 完整页面 URL |
| `page_path` | varchar(256) | 归一化路径（去 query，用于页面排行） |
| `referrer` | varchar(512) | 来源页（首跳直接访问为空） |
| `utm_source` / `utm_medium` / `utm_campaign` | varchar(128) | 渠道归因（可空） |
| `device_type` | varchar(16) | desktop / mobile / tablet（UA 判定） |
| `os` / `browser` | varchar(64) | 操作系统 / 浏览器（UA 解析） |
| `screen` | varchar(32) | 屏幕分辨率（客户端事件才有，服务端事件可空） |
| `lang` | varchar(16) | 界面语言（en/zh/fr） |
| `country_code` | varchar(8) | ISO 3166-1 alpha-2 |
| `country_name` / `province_name` / `city_name` | varchar(64) | 当地名（GeoLite2，城市级；海外到城市，东南亚到大城市级） |
| `province_code` | varchar(16) | ISO 3166-2（海外无省时为空） |
| `ip` | varchar(45) | 原始客户端 IP（**本期不脱敏**，IPv4/IPv6） |
| `duration_ms` | int | 停留时长（仅 `page_leave` 事件，单位 ms） |
| `props` | json | 扩展属性（如搜索词、曝光位置、点击元素、结果数、无结果标志） |

索引：

```sql
PRIMARY KEY (id),
KEY idx_event_time        (event_time),
KEY idx_org_event_time    (org_code, event_time),
KEY idx_product_event     (product_id, event_time),
KEY idx_event_name_time   (event_name, event_time),
KEY idx_session           (session_id),
KEY idx_visitor           (visitor_id, event_time)
```

**设计决定：**
- **不设 `del_flag`**：行为明细是账本，删除本身就是数据完整性事故（与订单 `order_event`/`stock_log` 同一原则）。
- **`org_code`/`store_id` 为快照**：采集时刻冗余店铺归属，事后店铺改绑不影响历史统计。
- **`visitor_id` 非登录态也唯一**：BFF 用随机 ID + httpOnly cookie，保证 UV 去重与登录无关（本期不做匿名化，原始 IP 照存）。
- **不建"访客表"**：`visitor_id` 即标识，留存/新老客在 Phase 3 用 summary 聚合，不单独建表。

### 3.3 `ck_shop_track_summary`（多维度汇总，长期保留）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | varchar(36) | 主键 |
| `stat_time` | datetime | 统计桶起点（整点或整天） |
| `granularity` | varchar(8) | `hour` / `day` |
| `org_code` | varchar(64) | 店铺归属；`ALL` 表示全局（超管视角） |
| `product_id` | varchar(36) | 商品维度；`ALL` 表示非商品维度 |
| `dim_type` | varchar(32) | `global` / `store` / `product` / `region` / `source` / `device` / `page` |
| `dim_value` | varchar(128) | 维度取值（如国家码、来源渠道、页面路径、商品 ID 冗余） |
| `pv` / `uv` / `ip_count` | bigint | 浏览量 / 去重访客 / 去重 IP |
| `visit_count` / `bounce_count` | bigint | 会话数 / 跳出会话数 |
| `total_duration_ms` | bigint | 停留总时长（求和） |
| `expose_count` / `click_count` | bigint | 曝光 / 点击（商品维度） |
| `add_cart_count` / `order_count` / `paid_count` | bigint | 加购 / 下单 / 支付（**从业务流水回填**） |
| `order_amount` / `paid_amount` | decimal(12,2) | 下单额 / 实收额（商品维度，供转化与 GMV 关联） |

唯一键：`uk_summary(stat_time, granularity, org_code, product_id, dim_type, dim_value)`。

**设计决定：**
- **单表承载"小时 + 日 + 多维度"**：`granularity` + `dim_type` + `dim_value` 三个字段区分桶，避免一张维度一张表。
- **UV 只在 `day` 粒度精确**（COUNT DISTINCT，量级 <10 万/天完全够）；`hour` 粒度 UV 用 HyperLogLog 近似并标注为估算值（跨小时不可直接相加）。
- **漏斗各步（加购/下单/支付）从业务表回填**，不依赖埋点事件，保证与订单统计 GMV 口径一致。

### 3.4 Redis 实时键（不落库，仅实时层）

| Key | 类型 | 用途 |
|---|---|---|
| `track:online` | ZSET（member=session_id, score=最后活跃 epoch ms） | 在线人数 = 清理 >60s 后 `ZCARD` |
| `track:pv:{yyyyMMddHHmm}` | String（`INCR`，TTL 2h） | 分钟级 PV，实时大盘取窗口内 `MGET` 求和 |
| `track:uv:{yyyyMMdd}` | HyperLogLog（`PFADD visitor_id`，TTL 3d） | 当日实时 UV（近似） |
| `track:rt:product:{product_id}:{yyyyMMdd}` | HyperLogLog | 商品实时访问人数（Phase 2，可选） |

## 4. 事件规范（埋点协议）

### 4.1 事件清单与采集分工

| 事件名 | 触发 | 采集层 | 备注 |
|---|---|---|---|
| `page_view` | 进入页面 | **BFF 中间件（无感）** | SSR 每次请求即一条；SPA 客户端路由跳转由 SDK 补一条 |
| `product_view` | 商品详情进入 | **BFF 中间件（路径可判定）** | 升级现有 `ck_shop_product.view_count`（明细为权威，`view_count` 降级为缓存） |
| `page_leave` | 离开 / 切后台 | 前端 `sendBeacon` | 带 `duration_ms`，算停留时长 |
| `product_expose` | 商品曝光 | 前端 `IntersectionObserver` | 视口内 50% 且停留 ≥500ms 计一次（懒上报、去重） |
| `product_click` | 商品点击 | 前端 | 带点击位置/商品 |
| `search` | 搜索 | 前端 | `props` 带搜索词 / 结果数 / 是否无结果 |
| `add_to_cart` | 加购 | **复用 `ck_shop_cart_event`** | 不埋点，防口径漂移 |
| `order_create` / `order_paid` | 下单 / 支付 | **复用 `ck_shop_order` / `ck_shop_order_payment`** | 不埋点 |

### 4.2 公共属性（每条事件都带）

`event_time, session_id, visitor_id, user_id?, org_code, store_id?, product_id?, page_url, page_path, referrer, utm_*, device_type, os, browser, screen?, lang, country_*, province_*, city_name, ip`

> `country/province/city` 由 **Java 端用 GeoLite2 解析 IP 得到**，BFF/客户端**不解析**（避免每次请求重复解析，也避免把 mmdb 加载到 Node 端）。BFF 只传原始 IP。

### 4.3 事件字段（仅列独有字段，公共属性略）

| 事件 | 独有字段 |
|---|---|
| `page_view` / `product_view` | —（`product_view` 必带 `product_id`） |
| `page_leave` | `duration_ms` |
| `product_expose` | `props.exposePosition`（列表位次）、`props.exposeProductIds`（批量曝光） |
| `product_click` | `props.clickPosition`、`props.target` |
| `search` | `props.keyword`、`props.resultCount`、`props.noResult` |

## 5. 采集与实时层设计

### 5.1 BFF 无感采集中间件（`nuxt-shop/server/middleware/analytics.ts`）

- 挂在**所有同源请求**的最外层，读到：URL、referrer、UA、`Accept-Language`、Cookie（session/visitor）、店铺 code（从路由/店铺上下文）、真实 IP（`X-Forwarded-For` 取第一个可信 hop，沿用项目既有 IP 解析约定）。
- **只做入队**：把事件对象塞进**内存环形队列**，立即返回，不等待落库。
- 批量 flush：队列达到 500 条 **或** 距上次 flush ≥ 2 秒，由独立异步 worker 批量 `POST /api/track/events`（内部）到 Java；flush 失败或超时**静默丢弃**（丢行为数据，绝不丢业务、绝不重试风暴）。

### 5.2 前端轻量 SDK（`nuxt-shop/app/plugins/analytics.ts`）

- 只补服务端看不到的：`page_leave`（`visibilitychange`/`pagehide` + `navigator.sendBeacon`）、SPA 路由 `page_view`、曝光（`IntersectionObserver` 懒上报）、点击、搜索。
- 性能约束：`requestIdleCallback` 延迟初始化、失败静默、**无轮询定时器**、曝光去重、批量合并。
- 停留时长：进页记 `entryTime`，离开时 `duration_ms = now - entryTime`，**只在离开时打一次点**，不做秒级心跳。

### 5.3 采集接收接口（Java）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/shop/analytics/track/events` | 批量接收事件（BFF 内部调用，`@IgnoreAuth` + 简单签名/限流） |

- Java 端收包后**异步入队 + JDBC 批量 insert**，不占用请求线程。
- 限流：单 IP/单签名每分钟上限，防止刷量打爆明细表（与"不引国内 SDK"无关，是通用保护）。

### 5.4 实时与聚合边界（关键）

- **秒级实时只给：在线人数 / PV / UV / 实时大盘核心指标**，全部读 Redis（§3.4），**不碰 MySQL**。
- **全事件漏斗明细**：异步批量落 `ck_shop_track_event`；漏斗/转化按**分钟级定时任务**聚合到 `ck_shop_track_summary`。
- 绝不做"秒级大表实时聚合"。强实时承诺由 Redis 兑现，性能由异步 + 汇总 + 隔离兑现。

### 5.5 IP → 地域（GeoLite2 City）

- Java 启动时把 `GeoLite2-City.mmdb` 加载进内存（`com.maxmind.geoip2`），采集写入时即时解析出 `country/province/city`。
- **原始 IP 直接落库**（本期不脱敏）；mmdb 文件随部署包分发，**不进 Git 仓库**（走 `.gitignore` + 部署注入）。
- 海外城市级精度：GeoLite2 City 覆盖良好（欧洲/东南亚到城市级，个别小地区回退到省/国家，前端做降级展示）。

## 6. 接口清单（管理端统计）

统一响应包装 `Result<T>`；权限码见 §6.2；店铺隔离复用 `ShopOrgScopeResolver`（非超管自动加 `sys_org_code` 范围）。

### 6.1 统计查询接口（`/shop/analytics/admin/**`）

| 方法 | 路径 | 说明 | 数据来源 |
|---|---|---|---|
| GET | `/realtime/overview` | 实时在线 / 今日 PV / 今日 UV / 今日核心指标 | Redis + 今日 summary |
| GET | `/trend` | 趋势（`granularity=hour/day`，按 `dim`） | summary |
| GET | `/rank/product` | 商品排行（访问 / 加购 / 转化率 / 停留） | summary（product 维度） |
| GET | `/funnel` | 转化漏斗（曝光→点击→加购→下单→支付） | summary + 订单表回填 |
| GET | `/region` | 地域分布（国家 / 省 / 市） | summary（region 维度） |
| GET | `/source` | 来源分布（直接/搜索/外链/UTM） | summary（source 维度） |
| GET | `/device` | 设备 / 浏览器 / 语言分布 | summary（device 维度） |
| GET | `/page` | 页面排行 / 平均停留 / 跳出率 | summary（page 维度） |
| GET | `/events` | 行为明细分页查询（导出用） | `ck_shop_track_event` |

> 每个接口独立暴露（沿用订单统计"大屏按需刷新"的约定）：总览 30s 刷、排行 5min 刷、明细按需。

### 6.2 权限码

| 权限码 | 含义 |
|---|---|
| `shop-analytics:view` | 查看行为统计（默认运营/店长） |
| `shop-analytics:export` | 导出明细 |
| `shop-analytics:all` | 全局汇总视角（超管，绕过 `sys_org_code` 范围） |

### 6.3 与既有订单统计的关系

- `ck_shop_order` 的 GMV/实收/退款口径**不变**，行为漏斗里的"下单/支付"直接引用订单统计口径，保证两处 GMV 对得上。
- 订单统计页（`ShopOrderStats`）不动；行为分析的漏斗/转化作为**新增独立页**，复用其风格。

### 6.4 接口返回字段（VO 约定，前后端并行开发的唯一依据）

统一 JSON `Result<T>`：`{ success, code, message, result, timestamp }`，`result` 为下述对象/数组。
金额一律字符串（`BigDecimal` → JSON 字符串，沿用订单统计约定）；时间格式 `yyyy-MM-dd HH:mm:ss`；字段名 camelCase。

## 7. 统计口径（权威定义）

| 指标 | 口径 |
|---|---|
| **PV** | 一次 `page_view`（SSR 请求 + SPA 路由跳转各计一次） |
| **UV** | 当日去重 `visitor_id`（day 粒度精确、hour 粒度 HLL 估算） |
| **IP 数** | 当日去重 `ip` |
| **会话** | 同 `visitor_id` 相邻事件间隔 ≤ 30 分钟归为同一会话 |
| **停留时长** | `page_leave` 的 `duration_ms`；会话内未正常 leave 的，按"最后活跃时间 − 进入时间"兜底，上限 30 分钟 |
| **跳出率** | 单页会话数 / 总会话数 |
| **曝光** | 商品视口内 50% 且停留 ≥ 500ms，同会话同商品去重 |
| **点击率** | 点击 / 曝光 |
| **加购率** | 加购 / 商品访问 |
| **转化率** | 下单 / 商品访问（漏斗逐步：访问→加购→下单→支付） |
| **商品访问量** | `product_view` 事件计数（权威），`ck_shop_product.view_count` 降级为排序缓存 |

## 9. 两条强制要求的落地保证

### 9.1 用户 100% 无感

- BFF 中间件在**必经链路**上零成本采集，无额外客户端脚本、无额外网络往返、无感知变化。
- 前端 SDK 只在"服务端看不到的行为"才存在，且 `requestIdleCallback` 延迟 + `sendBeacon` 卸载上报 + 失败静默 + 无轮询。
- 采集全程同源、无第三方域名请求（GA4 除外，且受 Cookie 同意开关控制）。

### 9.2 不影响系统性能

- BFF 只内存入队 → 批量 flush → 异步写；超时静默丢弃。
- Java 采集异步入队 + 批量 insert；明细与业务表隔离、只追加、按天归档（30 天）。
- 查询只走 summary + Redis，不实时聚合大表。
- 预留高基数事件采样开关（量级增长时启用）。

## 10. 合规（本期范围 + 风险提示）

**本期做：**
- Cookie 同意横幅（`nuxt-shop`，本地化 en/zh/fr）。
- GA4：**普通接入，不接 Consent Mode**（与 Cookie 同意横幅解耦，不因同意状态控制 GA4 加载）。

**本期不做（需求方明确）：**
- IP 脱敏（原始 IP 落库）、匿名化、数据主体删除/导出权、隐私政策页。

> ⚠️ **风险提示**：面向欧盟（GDPR）正式运营前，**必须**补上 IP 脱敏、匿名化、数据保留期限与删除/导出权、隐私政策，否则存在合规风险。本文档已把"原始 IP 落库"标为**临时实现**，届时改为 `ip_hash` 且 mmdb 解析不落原始 IP。

## 11. 分阶段实施

### Phase 1（核心，先做）
- BFF 无感采集 `page_view` / `product_view` + IP/来源/设备/语言/店铺。
- 前端 SDK 仅 `page_leave`（停留时长）+ Cookie 同意横幅。

- GeoLite2 City 解析落地。

- 复用：加购/下单/支付（漏斗先接订单表）。
- GA4 基础接入（Consent Mode）。

### Phase 2
- 前端 SDK 全事件（曝光/点击/搜索）。
- 商品漏斗/转化率/排行、地域/来源/设备报表。
- 自写精细分析页（多维度交叉）。

### Phase 3
- 留存 / 复购 / 路径分析。
- 风控（爬虫/刷量识别）。
- 明细归档清理自动化、GA4 深度看板、大屏高级化。
