**关键取舍**

- **合并「个人信息」进「账户资料」**：`?tab=info` 作为**兼容别名**仍可用（自动落到 `settings`），老书签/老链接不 404、不留空面板。
- **邮箱改为只读**：邮箱是登录标识（邮箱密码 / 邮箱验证码登录都靠它），换绑必须先验证新邮箱所有权，属于独立流程；页面给出"如需更换请联系客服"的明确指引，而不是给一个保存后必然被后端拒绝的输入框。

## 三、后端接口（ck-shop，均需登录，**不在** Shiro 白名单）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/shop/account/profile/update` | 保存昵称 + 手机号（真实落库） |
| POST | `/shop/account/profile/avatar` | 选择预设头像（白名单）或恢复默认（空串） |
| POST | `/shop/account/profile/avatar/upload` | 上传头像（multipart，字段名 `file`） |

三个接口**都返回最新的完整资料**（`ShopProfileVO`），前端直接用它刷新共享的 `userInfo`，不必再拉一次 `/profile`。

### 校验与安全边界

| 项 | 做法 | 为什么 |
|---|---|---|
| 用户 ID | 只从 Shiro 登录态取（`requireLoginUser()`），**绝不接受请求体传入** | 水平越权 |
| 账号资格 | `requireActiveShopCustomer()`：存在 + 未注销 + 未冻结 + 具备 `shop_customer` 角色 | `sys_user` 是管理端共用表，店铺端写接口不能变成管理端账号改资料的旁路 |
| 昵称 | 去控制字符/尖括号、折叠空白、1–30 字 | 空昵称会让资料卡退回通用称呼；`<`/`>` 是 HTML 注入常见载荷 |
| 手机号 | 去空格/短横线/括号后需匹配 `^\+?[0-9]{6,20}$`；**空串写 NULL** | `uniq_sys_user_phone` 是唯一索引，多个账号写空串会互相冲突；撞索引转成"该手机号已被其他账号使用" |
| 头像（预设） | 只接受 `ShopAccountConstant.PRESET_AVATARS` 里的 8 条站内路径或空串 | 否则"选头像"接口就成了可往库里写任意 URL 的入口（存储型追踪像素 / 外部资源引用） |
| 头像（上传） | **文件头魔数**判断真实类型（png/jpg/webp，不信 Content-Type 与扩展名）+ 2MB 上限 | 接口可被直接调用，不能假设调用方是我们的前端 |
| 头像 URL | 由**服务端**生成后写库（`{dir-prefix}/shop/avatar/{userId}-{时间戳}.{ext}`） | 文件名不含用户可控内容（防路径穿越），带 userId 便于运维定位，带时间戳避免同名覆盖 |
| 旧头像清理 | 换新头像 / 切到预设 / 恢复默认时，best-effort 删除旧的上传文件（仅限"确实指向本系统头像目录"的 URL；Google 头像与预设头像不删） | 不清理会在 OSS 里留下孤儿对象。⚠️ 实测：上传后**立刻**（<1s）切换时，upyun 偶发返回"删除失败"（推测是对象刚写入的最终一致性窗口），该次即成为孤儿，但**不影响功能**；后端日志会留一条 ERROR。如需彻底杜绝可加一次延迟重试，属后续优化 |

### 表结构

**无需迁移**：复用 `sys_user.avatar`（`varchar(255)`）。上传接口写库前校验 URL 长度，避免超长被 MySQL 截断。

## 五、顺带修掉的三个真实缺陷

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | 「保存修改」是**假保存** | 旧实现只把内容写进 localStorage 里那份显示缓存，服务端完全不知道；换设备/清缓存就变回原值 | 新增 `POST /api/auth/profile/update` 真写库；成功后用后端回读值刷新共享状态 |
| 2 | 统计卡「未开通」角标用错 key 且溢出卡片 | 页面直接显示 `profile.profileStatComingSoon`（未翻译），移动端角标顶出卡片边界 | 改用 `shop.profileStatComingSoon`；角标 `shrink-0` + 标签 `truncate`，长文案（法语 "Bientôt disponible"）不再撑破 |
| 3 | 订单/地址面板 hydration mismatch | 控制台 `Hydration completed but contains mismatches`，且空态→骨架闪一下 | 引入 `loaded` 状态，骨架条件改为「还没加载过」，SSR 与首帧客户端一致 |

## 八、运维 / 后续注意

1. **头像依赖 cik-oss**：`ck.oss.*`（`CK_OSS_*` 环境变量）不可用时，上传接口返回"头像上传失败，请稍后重试"；预设头像不依赖 OSS，仍可用。已实测本机 OSS 上传返回 `https://shop-img.cikian.cn/ck-shop/shop/avatar/...` 且可公开读取。
2. **预设头像清单两处同步**：后端 `ShopAccountConstant.PRESET_AVATARS` 与前端 `AvatarDialog.vue` 的 `PRESET_AVATARS` 必须逐字一致（增删预设时一起改；后端是真正的门禁）。
3. **旧链接兼容**：`?tab=info` 会落到「账户资料」，Header 下拉里的 `?tab=orders` / `?tab=favorites` 不受影响。
4. **邮箱换绑**（后续需求）：需要"给新邮箱发验证码 → 验证通过后换绑"的独立接口；本轮的只读处理是刻意的边界，不是遗漏。
5. **测试账号**：`probe.avatar@example.com` 仅存在于开发库，清理用 `.probe/ShopTestUserCreate.java --delete`。

```
└───────────────┴────────────────────────┘
```

左栏随滚动吸顶（`lg:sticky` + `top: nav 高度 + 24`），长表单滚动时头像与分区导航始终可见。

### 9.3 设计要点（以及"为什么"）

| # | 改动 | 理由 |
|---|---|---|
| 1 | 左栏 `minmax(260px,300px)` + 右栏 `minmax(0,1fr)` | 内容有稳定行宽；1760px 容器下不再把每段拉成横条 |
| 2 | 身份卡：品牌色**向下淡出**的晕染 + 右上明黄光斑 + 头像 92px 白环 | 原先的"104px 纯色矩形色带"在实机上有一条横贯卡片的硬边，像贴纸歪了 |
| 3 | 主操作独占一行、退出登录降级为中性文字链 | 两个等宽药丸并排时，法语 "Modifier le profil / Se déconnecter" 各折两行且高度不对称 |
| 4 | 分区导航同一 DOM 双排布（竖排卡片 / 横滑药丸） | 不重复渲染两套导航 → id 不撞、`aria-controls` 不歧义；键盘四向键都可用 |
| 5 | 数据卡：28px 黑体数字 + 图标 + 语义名，订单/收藏**可点直达** | 数字优先于文字（全站价格同理）；可点项 hover 出 `arrow-up-right`，未开通项不可点（不做无效点击） |
| 6 | 「未开通」改成数字位 `—` + 一行小字，不再是角标 | 角标在法语 "Bientôt disponible" 下会顶破卡片；现在也不显示 0（0 ≠ 未开通） |

| 9 | 响应式：数据卡 640px 起四列；身份卡内容在 <1024 时限宽 420px 居中 | 768 宽下单列时，700px 宽的"编辑资料"药丸看着像误拉伸；四列数据卡也不再有 360px 的空白卡 |

### 9.4 ⚠️ 踩到的真实坑：grid item 的 `min-width: auto`

第一次改造后移动端 390px 下 `document.scrollWidth` 变成 **442px**（整页被浏览器缩小、右边被截断）。

根因：`aside` 是 grid item，`min-width` 默认 `auto` = min-content；而它内部的分区导航是**横向药丸行**，
min-content 恰好是四个药丸的总宽（390px 下约 434px）。于是隐式列被撑到 434px，右栏跟着一起变宽。

修复：`aside` 加 `min-w-0`（右栏本来就有）。修完 `scrollWidth` 回到 390px。
**经验：任何放进 grid/flex 的"含横滑条或长文本"的容器，都要显式写 min-w-0。**

## 十一、第四轮：页面下方大片留白（真 bug，已修）

> 用户反馈（附截图，收货地址分区）："当前如图，下面没有内容，为什么要留白这么多呢"

### 11.1 实测数据（修复前，视口 1440×900）

| 量 | 值 | 说明 |
|---|---|---|
| `document.scrollHeight` | **1382** | 比视口高 482px |
| `main` / 页面根节点高度 | 900 / 900 | 页面根写了 `min-h-screen`（=100vh） |
| 最后一张卡片底边 | **591** | 内容其实只到 591 |
| 页脚 top | 964 | 内容与页脚之间有 **373px** 空白 |

### 11.2 两个叠加的原因

1. **`min-h-screen` + `pt-navbar` 双重占位**：布局里 `main` 本来就是 `flex-1`（页脚钉在视口底部），
   页面根再写 `min-h-screen` 就等于"在被导航下推了 116px 的位置又占满一整屏"。
   多出来的那一截可以滚，滚下去只是一片奶油色 —— 截图里卡片顶部被切掉，就是这个多余的滚动。
2. **短内容 + 页脚钉底**：内容（一张卡片）天然比视口矮，剩下的一大块空白裸露在卡片之外。

### 11.3 修法

| 位置 | 改动 |
|---|---|
| 页面根节点 | `min-h-screen` → `min-h-[calc(100vh-var(--nav-total-height))]`，并改成 `flex flex-col`（内容区与导航一起算，不再多出一屏） |
| 容器 / 网格 | `flex-1` 逐级传下去（container → grid），桌面上 `lg:items-stretch` |
| 左栏 `aside` | 加 `lg:self-start`（网格改成 stretch 后必须加，否则 sticky 失效） |
| 内容卡 | `ui-card flex flex-1 flex-col` —— 空白被白卡吃掉，变成卡片内部留白 |
| 面板容器 | `flex flex-1 flex-col` |
| 空态 | 订单 / 收藏 / 收货地址三个面板的空态加 `flex-1`，在伸展后的卡片里**垂直居中** |

### 11.4 修复后（同视口实测）

| 量 | 修复前 | 修复后 |
|---|---|---|
| 收货地址分区 卡片高 | 451 | **588**（撑满可用高度） |
| 内容底边 → 页脚 | 373px 空白 | 只剩 `pb-14` + 页脚自身外边距（约 120px 的正常区块间距） |
| 页面根高度 | 900（多出一屏可滚） | 784 = 100vh − 导航，不再有幽灵滚动 |
| 空白归属 | 裸露的奶油色空场 | 白卡内部留白（空态居中） |

其他断点（1920 → 375）复测：**0 横向溢出**；内容卡在各宽度下都填满可用高度。

> 备注：同样的 `min-h-screen` + `pt-navbar` 双写在其它 10 个页面也存在（/orders、/address、/cart 等），
> 表现为"短内容页可多滚一屏空白"。本轮只改了个人中心；如需要，可按同一套改法逐页处理。

## 十二、全站推广：把「幽灵滚动 / 下方大片留白」一次修干净

> 需求方确认："全部一起修"。

### 12.1 根因（所有页面同一个模板句式）

11 个页面根都是 `<div class="min-h-screen bg-[var(--color-cream)] pt-navbar">`，

### 12.2 改成两档
