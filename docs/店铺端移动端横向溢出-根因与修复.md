# 店铺端移动端「内容超宽 / 加载遮罩没盖满」——根因与修复

> 用户上报（2026-10-26，Edge Android，法语站）：**首页轮播图超宽、右侧内容被截断；
> 首屏的螺旋加载动画只盖住约 2/3 屏宽，右边露出页面内容。**
>
> 结论：**不是轮播图的问题，也不是加载动画写错了尺寸。**
> 首页首屏网格在 <1024px 时没有显式列定义，只剩一条隐式 `auto` 轨道；
> 该轨道的下限是子项的 min-content —— 而右列的分类药丸条（`overflow-x-auto` 横向滚动）
> 在法语下 min-content = **622px**，于是整列被撑到 **614px**、文档 `scrollWidth` 627 > `clientWidth` 390，
> **整页横向溢出 237px**。
>
> 移动浏览器（Edge/Chrome Android）一旦检测到横向溢出，会**把整页缩小**来塞进屏幕：
> `window.innerWidth` 变成 627 而 `documentElement.clientWidth` 仍是 390。
> 于是 `width:100vw` 的加载遮罩只有 390px 宽 → 只盖住 390/627 ≈ **62%** 的可视区域；
> 同时整页被缩小/截断，看起来就像"轮播图超宽"。
> **两个现象是同一个根因。**

---

## 1. 根因链

| # | 环节 | 事实 |
|---|------|------|
| 1 | 首页首屏网格只写了桌面列定义 | `app/pages/index.vue`：`class="grid gap-5 lg:grid-cols-[236px_minmax(0,1fr)]"`。<1024px 时 `grid-template-columns` 为空 → 隐式 `auto` 轨道 |
| 2 | `auto` 轨道的下限是 min-content | 网格子项 `div.space-y-4` 的 `min-width` 是 `auto`（flex/grid 子项的默认值），轨道宽度不能小于它的 min-content |
| 3 | 子项里有横向滚动条，但横滑**不降低** min-content | 分类药丸条 `no-scrollbar -mx-1 flex items-center gap-2 overflow-x-auto px-1 lg:hidden`。`overflow-x:auto` 只影响**绘制/滚动**，不影响 min-content 计算 —— 它的 min-content = 所有药丸宽度之和（法语 8 个分类名 ≈ 622px） |
| 4 | 列被撑破 | 列宽 614px > 可用 374px → 文档 `scrollWidth` 627 > `clientWidth` 390，溢出 237px |
| 5 | 浏览器缩小整页 | `window.innerWidth` 变 627、`clientWidth` 仍 390、`visualViewport.scale` 仍报 1（这是 Chrome 的实现细节，别拿 scale 判断有没有缩小） |
| 6 | 遮罩只盖 62% | `.page-loader` 用 `width:100vw`（= **布局视口** 390），而用户看到的是 627 宽的区域 → 390/627 ≈ 62% |

**为什么中文站没复现、法语站必现**：中文分类名短（"户外服装"/"露营装备"），
药丸条 min-content 小于视口，`auto` 轨道不越界；法语名长（"Vêtements outdoor" / "Équipement de camping"），
min-content 622px 直接撑破。**这不是"法语专属 bug"**：中文首页在 320 宽下同样溢出 36px（见下表）。

## 2. 证据（Edge headless + CDP，`.probe/overflow-root-cause.mjs`）

逐层量 min-content/宽度（390×844，DPR3，法语首页）：

```
[baseline] innerW=627 clientW=390 scrollW=627 溢出=237 bodySW=626
   container   w=390  scrollW=626  clientW=390
   grid        w=374  scrollW=618  clientW=374     ← 网格容器本身没超
   col         w=614  scrollW=618  clientW=614  minWidth=auto   ← 列被撑到 614
   chips       w=622  scrollW=622  clientW=622     ← 药丸条 min-content 622
   carousel    w=614  scrollW=1228 clientW=614     ← 轮播只是"跟着列变宽"，不是元凶
```

修复前溢出宽度（矩阵实测，`.probe/mobile-matrix-audit.mjs`）：

| 页面 | 320 | 360 | 390 | 414 | 430 |
|---|---|---|---|---|---|
| `/fr` 首页 | **306px** | **267px** | **237px** | **212px** | **196px** |
| `/zh` 首页 | **36px** | 0 | 0 | 0 | 0 |
| `/fr` 商品详情 | **68px** | **28px** | 0 | 0 | 0 |
| 其余 8 条路由 | 0 | 0 | 0 | 0 | 0 |

溢出元素 top1 恒为 `div.space-y-4 > div.no-scrollbar.-mx-1.flex.items-center`（分类药丸条），
与根因链第 3 步一致。

## 3. 修复（4 处 + 1 个顺手修掉的既有 bug）

### 3.1 `app/pages/index.vue` —— 根因

```diff
-<div class="grid gap-5 lg:grid-cols-[236px_minmax(0,1fr)]">
+<div class="grid grid-cols-1 gap-5 lg:grid-cols-[236px_minmax(0,1fr)]">
```

`grid-cols-1` = `repeat(1, minmax(0, 1fr))`，**min 是 0 不是 auto**，
轨道宽度只由容器决定；药丸条退化成"在列内自己横滑"。

### 3.2 `app/pages/profile.vue` —— 同类 bug（静态排查发现）

个人中心已登录态 `grid gap-6 lg:grid-cols-4` 是同一个模式：右栏标签条
（Profil / Mes commandes / Mes favoris / Adresses / Paramètres）min-content = 606px，
会把 374px 的列撑到 606px（溢出 231px）。同样加 `grid-cols-1`。

### 3.3 `.page-loader` 加固（`app/assets/css/tailwind.css`）

```diff
-.page-loader { top: 0; left: 0; width: 100vw; height: 100dvh; }
+.page-loader {
+  top: 50%; left: 50%;
+  width: 300vw; height: 300dvh;   /* 3 倍视口，最多容忍 1.5 倍视口宽的溢出 */
+  transform: translate(-50%, -50%);
+}
```

布局已经修掉了这次溢出，但遮罩不能再依赖"页面永远不溢出"这个前提：
`100vw` 永远只等于**布局视口**，一旦将来某个页面再溢出，遮罩又会只盖 62%。
3 倍尺寸以布局视口中心为锚点，螺旋仍精确居中（实测中心误差 0px）。
`position: fixed` 的元素**不参与文档滚动溢出计算**，所以放大不会反过来制造横向滚动。
保留 `vw/dvh` 而不是 `inset:0` 的原理由仍然成立：`html` 上有 `scrollbar-gutter: stable`，
`inset:0` 只铺到内容区宽度，桌面端右边会漏 10px（实测 1440 视口：`clientWidth` 1430，
遮罩 rect 覆盖 -1445..2875，不漏）。

### 3.4 `.ui-action-dock` 极窄屏（`app/assets/css/tailwind.css`）

矩阵扫出的第二处真溢出：商品详情底部动作条的两个主按钮是 `flex-1`，
但作为 flex 子项 `min-width` 仍是 `auto` = min-content；按钮文案带 `truncate`（nowrap），
法语 "Ajouter au panier" + "Acheter maintenant" 把最小行宽顶到 384px：

```css
@media (max-width: 399px) {
  .ui-action-dock .ui-pill:not(.ui-pill-fav) { min-width: 0; }
}
```

**为什么带断点**：≥400px 时 384px + 左右各 16px 内边距仍放得下（390 实测 0 溢出、文案不省略）；
只有 <400px 才收缩并用省略号收尾。无条件 `min-width:0` 会让 390 宽的
"Acheter maintenant" 也被截断 —— 那是给用户手机引入新回归。

### 3.5 顺手修掉：`prefers-reduced-motion` 下遮罩永不消失（既有 bug）

`@media (prefers-reduced-motion: reduce)` 里的 `animation: none !important` 把
14s 的 `page-loader-safety` 兜底动画一起干掉了。实测（模拟 reduce）：
改前 14.6s 后仍是 `visibility:visible / pointer-events:auto` ——
**JS 一旦挂了，整页会被遮罩永久盖住**。现在把 `.page-loader` 从那条
`animation:none` 列表里移出（装饰性动画照旧关闭），14.6s 后正常
`visibility:hidden / opacity:0 / pointer-events:none`。

## 4. 验证

### 4.1 矩阵（`.probe/mobile-matrix-audit.mjs`）

zh/fr × 320/360/390/414/430 × 11 条路由 = 110 例，**生产构建**（`BASE=http://127.0.0.1:3001`）：

* 判定：`scrollWidth <= clientWidth` **且** `window.innerWidth === clientWidth`（后者证明没被整页缩小）；
* 结果：**110/110 PASS，FAIL 0** —— `88` 例直接测出，其余 `22` 例因并发跑探针导致水合 >12s
  被判 `??`（不确定，实测数字同样是 `ovf=0`），空载复测 **25/25 PASS**；
  合并后 11 条路由 × 5 宽度 × 2 语言全部 `innerW === clientW === scrollW`，横向溢出 0。
* 修复前基线（同脚本对同一页面摘掉 `grid-cols-1` 模拟）：见 §2 表格
  （fr 首页 306/267/237/212/196px，与修复后 0 一一对应）。

### 4.2 加载遮罩

| 检查 | 结果 |
|---|---|
| 首帧 rect 完全包含视口（390×844） | `{x:-390, y:-844, w:1170, h:2532}` ✔ |
| 螺旋视觉中心 = 视口中心 | `(195,422)` vs `(195,422)`，误差 0 ✔ |
| 桌面 1440×900 覆盖 `scrollbar-gutter` 10px 槽 | 覆盖 1440 与 1430，右侧不漏 ✔ |
| `prefers-reduced-motion: reduce` 下 14s 安全淡出 | 14.6s 后 `visibility:hidden / opacity:0 / pointer-events:none` ✔ |
| 水合后遮罩消失（6s） | 元素已从 DOM 移除 ✔（生产构建实测；防止"永久白屏 + 螺旋"） |
| 「将来再溢出」模拟（把网格改回 auto 轨道制造 627 溢出） | 旧 `100vw` 盒子覆盖 62%（不通过），新 300vw 盒子覆盖 100% ✔ |

专项脚本 `.probe/loader-acceptance.mjs` 41 项断言全绿（`loader-acceptance-prod-3001b.json`：
覆盖/居中/不透明/`position:fixed`/z-index/首帧出现/水合后消失/桌面 gutter/reduce 下 14s 放开/无静默裁剪）。
另有一条**决定性复核**：在 320/360 宽的商品详情上注入 `min-width:auto !important` 后
溢出**重新出现**（68px / 28px），证明 §3.4 的媒体查询确实在兜真实溢出，不是测量噪声。

### 4.3 横向滚动容器没有被误伤

分类药丸行、轮播幻灯片行、热销横滑、秒杀条、`/products` 筛选 chips、
商品详情锚点 chips、订单状态 tabs、图集缩略图：仍然
`scrollWidth > clientWidth` 且 `overflow-x` 为 auto/scroll，只是不再撑破文档。

### 4.4 桌面回归

≥768px 的布局与修复前一致（`grid-cols-1` 只在 <1024px 生效，
`lg:grid-cols-[236px_minmax(0,1fr)]` / `lg:grid-cols-4` 未改）；
动作条 `min-width:0` 只在 <400px 生效。

## 5. 回归面与注意

1. **这类 bug 的通用形态**：`grid`/`flex` 容器只写 `lg:` 列定义 + 子项里有横向滚动条。
   新写页面时，移动端要么显式 `grid-cols-1`，要么给子项 `min-w-0`。
   `overflow-x:auto` 只解决"内容怎么滚动"，**不解决"父容器被 min-content 撑破"**。
2. **不要用 `html/body { overflow-x: hidden }` 兜底**：实测它既不能阻止浏览器缩小整页
   （`scrollWidth` 仍 627），又会把 body 变成滚动容器，破坏 `position: sticky` 与
   `scrollbar-gutter: stable` 的既有约束（见 tailwind.css 里那两段注释）。
3. **判断"是否被整页缩小"要看 `innerWidth` vs `clientWidth`**，不要看
   `visualViewport.scale`（溢出的那种缩小它仍报 1）。
4. 手机端看到的是**生产构建**（`nuxt.frp.cikian.cn` → 本机 3001）：
   改完 CSS 必须 `npm run build` + 重启 3001，手机端强刷一次才生效。
   详见 `docs/店铺端移动端点击失效-根因与修复.md` §4。
