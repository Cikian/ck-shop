# 店铺端移动端「按钮点了没反应」——根因与修复

> 用户上报：**店铺端（nuxt-shop）PC 端点击都正常，手机端除了商品卡片能点，其他各种按钮点了都没反应。**
>
> 结论：**手机端访问的是 frp 隧道域名 `nuxt.frp.cikian.cn`（隧道指向本机 3000 的 `nuxt dev`），
> Vite 开发模式的客户端入口 URL 里带 `node_modules` 绝对路径，被隧道前置的 nginx 直接 404，
> 客户端 JS 从未下载/执行 → 页面只有 SSR 的 HTML：`<a>` 链接能点（浏览器原生跳转），
> 所有 `@click` 按钮全都没反应。** 与业务代码无关。

---

## 1. 根因链

| # | 环节 | 事实 |
|---|------|------|
| 1 | 手机走的是隧道域名 | `C:\frp` / `D:\Program Files\CikPier\frpc-store.json` 里代理 `nuxt`：`localPort 3000`，域名 `nuxt.frp.cikian.cn`（`nuxt.config.ts` 的 `vite.server.allowedHosts` 也是为它加的） |
| 2 | 隧道前置 nginx 会拦截"内部路径" | 任何 URL 里含 `node_modules`（以及 `.nuxt` 这类点目录）的请求，**不进内网、直接由 nginx 返回 146 字节的 404 页面** |
| 3 | dev 模式的客户端入口正是这种 URL | SSR 出来的 HTML 里写的是 `/<base>/E:/CProject/ck-shop/nuxt-shop/node_modules/nuxt/dist/app/entry.async.js`（Vite 把模块按**绝对文件路径**暴露）→ 404 |
| 4 | 客户端 bundle 404 = 永不水合 | `#__nuxt` 上没有 `__vue_app__`；Vue / vue-router / 所有 `@click` 监听器都不存在 |

页面样式是正常的（CSS 走 `/_nuxt/E:/.../app/assets/css/tailwind.css`，路径不含 `node_modules`，能穿过隧道），
所以**看起来一切正常，只是点不动**——这正是这个 bug 容易被误判成"前端代码写错了"的原因。

## 2. 证据（实测）

```powershell
# ① 同一个 dev server，同一个文件：localhost 200，隧道 404
curl.exe -sS -o NUL -w '%{http_code}\n' 'http://127.0.0.1:3000/_nuxt/E:/CProject/ck-shop/nuxt-shop/node_modules/nuxt/dist/app/entry.async.js'   # 200
curl.exe -sS -o NUL -w '%{http_code}\n' 'https://nuxt.frp.cikian.cn/_nuxt/E:/CProject/ck-shop/nuxt-shop/node_modules/nuxt/dist/app/entry.async.js' # 404（nginx，Content-Length: 146）

# ② 同形状但路径里没有 node_modules 的请求，隧道正常放行（说明规则是按路径内容拦的，不是按域名/前缀）
curl.exe -sS -o NUL -w '%{http_code}\n' 'https://nuxt.frp.cikian.cn/_nuxt/E:/CProject/ck-shop/nuxt-shop/app/pages/index.vue'  # 200（42785 字节，Vite 转译后的 JS）
```

浏览器侧（`.probe/mobile-menu-ab.probe.mjs`，真机触摸事件 + 移动视口 390×844）：

| 环境 | 客户端是否水合 `__vue_app__` | 点「菜单」按钮（touchstart/click 事件都正常到达） | `/_nuxt/*` 失败请求 |
|------|------|------|------|
| `http://127.0.0.1:3001`（**生产构建**） | ✅ 是 | ✅ header 128 → 605，菜单展开 | 无 |
| `https://nuxt.frp.cikian.cn`（隧道 → dev，**修复前**） | ❌ **否** | ❌ header 128 → 128，毫无反应 | `404 .../node_modules/nuxt/dist/app/entry.async.js`、`404 .../.nuxt/nuxt-fonts-global.css` 等 |
| `https://nuxt.frp.cikian.cn`（隧道 → 生产构建，**修复后**） | ✅ 是 | ✅ header 128 → 605，菜单展开 | 无 |

关键点：**两边的 `touchstart`/`click` 浏览器事件都照常触发**——所以这不是"移动端点击事件被吞了"，
而是"JS 从来没跑起来，没人监听这个 click"。

## 3. 修复

### 3.1 必做：手机端用**生产构建**，不要让隧道指向 `nuxt dev`

生产构建的资源是 `/_nuxt/<hash>.js|css`（不含 `node_modules`、不含绝对路径），可以正常穿过隧道：

```powershell
cd nuxt-shop
npm run build                      # 产出 .output/
$env:PORT=3001; npm start          # 生产服务（脚本已内置 --env-file-if-exists=.env，会读到 STORE_CODE/API_BASE_URL 等）
```

然后在 **CikPier 界面**里把代理 `nuxt` 的 **localPort 从 3000 改成 3001**（保存即生效，域名不变）。
这样：

* 手机（隧道域名）→ 生产构建 → 一切按钮正常；
* 本机开发（`localhost:3000`，`npm run dev`）→ 不受影响，HMR 照旧。

> 为什么不推荐"让隧道放行 node_modules"：那等于把 `node_modules` 暴露到公网，
> 而且是服务商侧的 nginx 规则，本地改不了；dev 服务器对外提供访问本身也不该是长期方案。

**当前落地状态（已生效并实测）**：隧道 `nuxt` 代理已指向 **3001**，
生产服务 `node .output/server/index.mjs` 正跑在 3001（本次改动的 CSS 已打进这一版构建），
`https://nuxt.frp.cikian.cn/zh` 的 HTML 引用 `/_nuxt/CTpivGRQ.js`（不再有 `node_modules` 入口），
CSS 里已含 `--nav-total-height` / `--nav-search-height`。手机端如仍是旧页面，强制刷新一次即可。

> 注意：改完代码后需要 `npm run build` 并重启生产服务，手机端才会看到新版本；
> 开发时用 `localhost:3000`（HMR）即可，不要指望隧道域名能看到实时改动。

### 3.2 已完成（代码侧）：修掉另一个"移动端专属"的点击问题

排查时同时发现：移动端固定导航（Logo 行 + 搜索行 = **实测 128px**）比内容区预留的
`.pt-navbar`（用的是单行 token `--nav-height: 64px` → 只有 80px）**高出 48px**，
所以**每页顶部 48px 的内容被 fixed header 盖住**，点下去落在 header 的搜索框上：

* 首页移动端整行分类药丸（户外服装/露营装备/…）被完全盖住 → 看不见也点不到；
* 商品页/分类页的面包屑、商品页标题在 header 底下；
* 详情页吸顶锚点条的 SSR 首帧 top 也是按一行算的。

修复：`app/assets/css/tailwind.css` 把导航高度拆成三个 token 并给出**总高度**
（移动端 `64 + 64 = 128px`，桌面 `116px`），`.pt-navbar`、`scroll-padding-top`、
详情页吸顶条的 SSR 回退值统一用 `--nav-total-height`：

```css
--nav-height: 64px;            /* 移动端第 1 行 */
--nav-search-height: 64px;     /* 移动端第 2 行：搜索行（含 1px 上边框） */
--nav-height-md: 116px;        /* 桌面端：搜索行 + 分类行 */
--nav-total-height: calc(var(--nav-height) + var(--nav-search-height));
@media (min-width: 768px) { :root { --nav-total-height: var(--nav-height-md); } }
```

实测（`.probe/measure-nav.probe.mjs`）：

| 视口宽 | header 实测高 | 修复前内容预留 | 修复后内容预留 |
|---|---|---|---|
| 320–767px | 128px | 80px ❌（盖住 48px） | **144px** ✅ |
| 768–2550px | 117px | 140px ✅ | 140px ✅（未变） |

`.probe/mobile-coverage.probe.mjs`（逐个可交互元素做 `elementFromPoint` 命中测试）修复前
首页有 4 个、分类页 1 个、商品详情页 3 个元素"中心点命中的不是自己"，修复后全部为 0。

## 4. 日常操作：生产构建与启动

一键脚本：**`nuxt-shop/start-prod.bat`**（纯 ASCII + CRLF 写的，cmd 下不会有编码/解析问题）

| 操作 | 做什么 |
|---|---|
| 双击 `start-prod.bat` | 用现有 `.output` 直接启动（秒起），关掉窗口即停止 |
| `start-prod.bat build` | 先 `nuxt build` 再启动（**改过代码后用这个**） |

等价的手动命令：

```powershell
cd nuxt-shop
npm run build                  # 产出 .output/（约 2 分钟）
$env:PORT=3001; npm start      # 生产服务；端口必须 3001 = CikPier 里 nuxt 代理的 localPort
```

三个必须知道的点：

1. **重新构建前先停掉旧的生产服务**。`nuxt build` 会重建 `.output`，旧进程还在跑时它引用的旧资源文件名（`/_nuxt/<hash>.js`）已经被删掉，
   手机端会白屏/点不动。正确顺序：关掉生产服务窗口 → `start-prod.bat build`。
2. **服务不会自己开机启动**。窗口关掉或电脑重启后，`https://nuxt.frp.cikian.cn` 会直接打不开（隧道那一端是通的，只是本机 3001 没人监听）。
   需要开机自启就注册一个登录时任务（路径无空格，可直接用）：
   ```powershell
   schtasks /create /tn "ck-shop-prod" /sc onlogon /tr "cmd /c E:\CProject\ck-shop\nuxt-shop\start-prod.bat" /f
   # 删除：schtasks /delete /tn "ck-shop-prod" /f
   ```
3. 开发用 `localhost:3000`（`npm run dev`，有 HMR）；生产服务在 3001。**两者互不影响，不要对调端口**——
   如果 3000 被生产构建占用，PC 上的开发会失去热更新，很容易误判成"改了代码没生效"。
