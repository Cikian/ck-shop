# 商品详情页「真实统计」与评价模块 · 验证记录

日期：2026-10-21 ｜ 环境：本机 MySQL 5.7.26（库 `ck-shop`）+ 后端 9951 + 前端 dev 6001

## 1. 要解决的问题（一句话）

商品详情页统计行的三个数字（已售 2068 / 4.5 / 收藏数 2653）**没有一个能对上业务流水**：
它们来自 `ck_shop_product` 的冗余列，而这些列是当年演示脚本写死的常量。
本轮把它们换成可追溯的真实口径，并为「评分/评价数」补上真实评价模块（此前库里没有评价表）。

| 统计项 | 真实来源 | 结果 |
|---|---|---|
| 已售 | `ck_shop_order_item` ⋈ `ck_shop_order`（已支付、未取消/关闭，件数扣已退） | 实时聚合 |
| 评分 / 评价数 | 新增 `ck_shop_product_review`（一条订单明细只能评价一次） | 实时聚合 |
| 收藏数 | `ck_shop_favorite`（`del_flag=0` 行数） | 实时聚合 |

冗余列（`sales_count / month_sales_count / favorite_count / review_count / rating_avg`）
降级为**排序与后台统计用的缓存**，由迁移脚本与写入事务同步维护。

## 5. 顺带修掉的一个真实故障（阻断级）

`ShopPaymentServiceImpl.paymentMapper` **缺少 `@Autowired`**（字段被重构时注解丢了），
运行时为 `null` → **所有支付都发不出去**：

```
Cannot invoke "ShopOrderPaymentMapper.selectOne(...)" because "this.paymentMapper" is null
```

没有支付就没有"已支付订单"，销量统计自然永远是 0 —— 这也是本轮"真实统计"必须先修它的原因。
已补回注解并加注释说明为什么不能删。

## 7. 已知取舍（明确写下来，避免下次误判为 bug）

1. **演示商品现在几乎全是 0**：库里真实已支付订单很少，页面统计行大部分商品不渲染 —— 这是"真实优先"的必然结果，不是渲染 bug。
2. **评分星级用颜色区分**：项目统一用 iconify CSS 模式渲染 `lucide:star`，实心/空心靠 `text-[--color-accent-500]` 与 `text-[--color-line]` 的颜色差，`fill-current` 在该模式下无效（既有写法，全站一致）。
3. **只有已支付订单能评价**：`pay_status ∈ (PAID, PARTIAL_REFUND)` 且订单未取消/关闭；全额退款后不可评价。
4. **待评价明细只在订单详情打开时拉一次**：刚支付完在别的标签页也不会自动刷新（刷新页面即可）。
5. **后台评价管理页未做**：表里已留 `status`（Y 展示 / N 隐藏）与 `del_flag`，但还没有后台菜单与审核界面。
